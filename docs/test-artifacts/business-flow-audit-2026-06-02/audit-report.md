## 覆盖链路

- 账号创建、登录、注册、审核、驳回、审核后登录。
- 程序提供商创建管理员后台账号，并验证权限只能层层下发。
- 管理员配置预约、用户领取策略、区域、柜机、货品、批次、仓库调拨、盘点。
- 用户查看额度、附近柜机、预约、取消预约、预约开柜、柜门回调、结算回调、领取记录。
- 商家注册审核、登录、常用商品、补货开柜、补货登记、补货追踪。
- 异常反馈创建、后台处理、用户查看处理状态。
- 未登录、角色越权、权限越权、错误输入、库存不足、预约关闭、伪造柜机回调等边界。

## 已修复问题

1. 柜机货品查询在本地回退时展示旧库存，导致用户看到“有货”但预约提示“最多 0 件”。
   - 修复：设备货品查询回退路径改为读取当前批次库存。

2. 登录用户提交反馈时，后端没有绑定当前登录用户，导致后续“我的反馈处理结果”可能查不到。
   - 修复：反馈接口保持可匿名提交；如果带登录 token，则以后端识别到的登录用户为准。

3. 新增区域时，空名称会先提示“请填写地区经纬度”，错误焦点不清楚。
   - 修复：先校验区域名称，再校验经纬度；文案统一为“区域”。

4. 客服电话语义过重，容易变成“不会操作就打电话”。
   - 修复：仅在“柜机异常”反馈场景展示“柜机异常？请联系客服电话”，服务问题走提交反馈。

5. 后台和部分后端展示文案仍残留“特殊群体 / 爱心商户 / 商户”作为角色称呼。
   - 修复：面向用户和管理员的角色文案统一为“用户 / 商家”；支付配置里的“商户号”等行业术语保留。

6. 原主链路 E2E 选货逻辑在库存不足时会退回第一件 0 库存货品。
   - 修复：测试脚本改为选择 `stock >= 1` 的可用货品，并把库存值写入断言信息。

## 仍需产品 / 部署确认

- 本地开发目前存在移动端 H5 和后台都监听 5173 的混用风险，一个绑定 `localhost`，一个绑定 `127.0.0.1`。建议后续固定为移动端 5173、后台 5174。
- 本地审计为了使用默认 `super/super123`，仅对本地 API 进程临时设置了 `ALLOW_DEFAULT_BACKOFFICE_LOGIN=true`；公网必须保持禁用默认后台密码并改用正式凭据。
- 当前首版仍使用内存仓储和本地持久化文件，公网真实运营前应按 ADR 后续计划迁移正式数据库或至少明确备份恢复策略。
- SmartVM 真实签名回调、真实微信支付/退款、微信开发者工具真机体验仍需在公网或预发布环境再验收。
- 反馈处理完成目前会弹窗提醒用户；如果希望更轻量，可后续改为首页提醒条或消息中心。
