# 真实入口、外部凭据与数据平面配置说明

## 结论与当前状态

正式实例分为两种生产配置：即时领取并真实收款，或预约取货且关闭支付。预约取货正式实例不要求微信、支付宝或支付对账配置；选择后台签发一次性人工验证码时，也不要求阿里云 PNVS。两种正式配置都必须使用独立 `live` 数据平面、HTTPS、单 API 工作者、金融单写者、审计和备份门禁。有柜机的实例必须接入生产 SmartVM；尚未录入柜机的新实例可显式设置 `SMARTVM_MODE=disabled`，录入首台柜机前必须改为 `real` 并完成生产接入。非生产时会读取 `.env.example`，其中的样例值绝不能当作真实凭据。

按“缺什么、由谁去哪里取得、系统为什么需要、如何安全交接和怎样验收”执行的清单见[实机部署缺口与外部凭据清单](实机部署缺口与外部凭据清单.md)。

本次改造把数据运行态划分为独立的两个 data plane，而不是由 URL、账号、路由或租户参数临时切换：

| 平面 | `VM_DATA_PLANE` | 用途 | 外部能力 | 数据要求 |
| --- | --- | --- | --- | --- |
| 模拟 | `simulation` | 本地联调、审计证据、测试货品与测试账号 | 强制 mock 验证码、mock 支付和 SmartVM mock；禁止配置真实短信、支付或柜机凭据 | 保留现有测试数据和审计证据 |
| 真实 | `live` | 真实上线 | 已有柜机时使用供应商生产柜机；零柜机实例可暂时关闭柜机接入；验证码可选 PNVS 或后台一次性人工码；预约取货可关闭支付，其他流程必须使用真实支付；禁止 mock 降级 | 纯净库；不得带测试用户、测试货品、模拟设备、模拟支付或默认密码 |

真实与模拟必须运行在不同进程/服务实例，并使用不同 `VM_DATA_ROOT`、反向代理上游、服务用户、CORS 来源和受控配置来源。不得共用状态文件、系统审计日志、上传目录、备份目录或金融单写者租约。任一 `VM_DATA_ROOT` 或 `VM_DATA_PLANE_ID` 已设置而遗漏 `VM_DATA_PLANE` 时，进程会失败关闭，不能默认落入模拟库。

## 旧会话撤销是什么意思

旧会话撤销指：密码、账号状态、角色或后台归属发生安全变化后，服务端立即使此前签发的 Bearer token 失效；用户的已登录设备下一次请求必须重新认证，不是等待会话自然过期。当前普通会话上限为 24 小时，资料草稿上限为 30 分钟；会话、验证码和草稿均不写入业务快照，API 重启后不会恢复。

当前规则如下：

- 本人正常改密：验证当前密码，撤销该账号全部旧会话，只签发一个新的后台会话。
- 本人忘记密码：使用手机号验证码进入 `POST /api/auth/backoffice-password-reset`，成功后撤销全部旧会话，要求重新登录。
- 超级管理员重置：仅 `super_admin` 可调用 `POST /api/auth/backoffice-password-reset-as-super-admin`；必须提供目标账号、后台角色、新密码和原因，成功后撤销目标全部旧会话。
- 普通后台管理员：即使拥有账号管理权限，也不能为已有账号传入密码；通用账号配置接口只允许创建新凭据或修改非密码授权信息。
- 停用、角色变更或删除：立即撤销关联会话和资料草稿。

真实平面禁用历史 `admin-password-login` / `admin-password` 双凭据入口，只保留统一的 `backofficeCredentials`。这避免同一人员存在两套不同密码、改了一套而旧入口仍可登录的问题。

## 数据平面与初始化

### 必填部署变量

| 配置项 | 真实入口要求 | 说明 |
| --- | --- | --- |
| `NODE_ENV`、`APP_ENV` | `production` | 任一值为 production 都启用严格门禁。 |
| `VM_DATA_PLANE` | `live` | 只能由进程管理器/部署系统注入，系统设置接口不能在线切换。 |
| `VM_DATA_ROOT` | 必填、独立私有目录 | 由它统一派生 `store.json`、`system-audit.ndjson`、`uploads/`、`backups/`、`financial-writer.lock`。 |
| `VM_DATA_PLANE_ID` | 必填、稳定且唯一 | 8–128 位字母、数字、点、下划线或连字符；同一个真实数据根始终保持不变，用于拒绝跨实例恢复。 |
| `VM_PLATFORM_TENANT_NAME` | 必填、部署级名称 | 1–100 个单行字符；真实库初始化时与数据平面 ID、`PUBLIC_BASE_URL` 一起固化为唯一当前实例租户，不可由在线系统设置热改。 |

真实平面**不能**同时设置 `API_DATA_FILE`、`SYSTEM_LOG_FILE`、`UPLOAD_DIR`、`API_BACKUP_DIR` 或 `FINANCIAL_SINGLE_WRITER_LEASE_FILE`。这些单独路径仅兼容模拟平面；真实平面若检测到任一项会失败关闭。

运行状态与备份清单都带有 `{ dataPlane, instanceId }`。真实库还必须持久化且仅持久化一个当前实例租户：其 ID 等于 `VM_DATA_PLANE_ID`，实例 URL 等于 `PUBLIC_BASE_URL`，名称等于 `VM_PLATFORM_TENANT_NAME`。恢复前 marker 与租户均必须匹配当前受控部署配置；旧版未声明数据平面的备份仍可做只读校验和审计留存，但不能恢复。

### 创建纯净真实库

不要清空或复制当前模拟库。真实库仅可使用受控初始化命令创建；该命令要求 `VM_DATA_ROOT` 没有遗留审计、上传、备份或租约文件，拒绝覆盖任何已有真实业务或账号数据，并创建首个非默认服务商。初始密码只可由安全终端/密钥管理器提供；从已验收模拟入口升级时，可改用 `VM_INITIAL_CREDENTIAL_SOURCE_DATA_FILE` 只迁入已改密的服务商与首管理员密码散列。迁入模式不复制模拟用户、货品、柜机、支付、预约或日志，也不读取密码明文。

```powershell
# 以下变量应由服务管理器或受控密钥管理器注入；不要把密码写进脚本、终端历史或 .env.example。
$env:VM_DATA_PLANE = 'live'
$env:VM_DATA_ROOT = '<独立真实数据根目录>'
$env:VM_DATA_PLANE_ID = '<该数据根固定的唯一标识>'
$env:VM_PLATFORM_TENANT_NAME = '<该真实实例的运营显示名称>'
$env:PUBLIC_BASE_URL = 'https://<该实例的受控HTTPS域名>'
$env:VM_INITIAL_SUPER_ADMIN_USERNAME = '<首个超级管理员用户名>'
$env:VM_INITIAL_SUPER_ADMIN_PHONE = '<首个超级管理员手机号>'
$env:VM_INITIAL_SUPER_ADMIN_NAME = '<显示名称>'
# VM_INITIAL_SUPER_ADMIN_PASSWORD 必须通过安全终端/密钥管理器注入。

npm run init:live-data -- --confirm-live-initialization
```

迁入现有凭据散列时，另由受控部署临时提供 `VM_INITIAL_CREDENTIAL_SOURCE_DATA_FILE` 和 `VM_INITIAL_TENANT_ADMIN_USERNAME`；来源文件必须归服务用户所有且权限为 0600，两个来源账号都必须已经改掉默认密码。

预约取货实例先用版本化命令从当前 0600 配置生成独立候选配置。命令只继承公网、地图和可选 AI 项，强制关闭支付、选择人工码，并将新实例柜机接入设为 `disabled`；SmartVM、微信、支付宝、PNVS、模拟路径和测试柜参数不会进入目标配置：

```bash
npm run prepare:live-reservation-config -- \
  --source-env=/受控/当前.env \
  --target-env=/受控/候选.env \
  --data-root=/受控/独立-live-数据根 \
  --data-plane-id=<稳定实例标识> \
  --tenant-name=<正式实例名称> \
  --public-base-url=https://vending.5gogogo.top
```

公网入口必须显式传入无路径的 HTTPS 根地址；目标配置的 `PUBLIC_BASE_URL` 与 `CORS_ORIGINS` 都固定为该地址，不继承旧实例入口。目标文件采用 0600 原子创建且拒绝覆盖；输出只包含键数和 SHA256，不输出任何配置值。

初始化完成后才能启动 API。启动门禁还会检查：真实平面 marker、唯一且匹配部署的实例租户、有效的非默认服务商、无旧管理员凭据、无模拟柜机/支付单、审计日志就绪、状态完整性、HTTPS/CORS、验证码实现、柜机接入状态和单写者。本次凭据迁入模式还会原子创建一个有效首管理员；任一来源账号不合格都不会写入目标库。`SMARTVM_MODE=disabled` 只允许零柜机状态，任何柜机记录都会使生产就绪检查失败；`SMARTVM_MODE=real` 才要求生产 HTTPS 地址、签名凭据和来源约束。`PAYMENT_MODE=real` 时还检查真实支付与自动对账；`PAYMENT_MODE=disabled` 只允许预约取货且账本必须为空。即使 `NODE_ENV` 误设为开发环境，`live` 仍不能使用 mock 支付、mock 短信、mock SmartVM、未签名回调或测试柜机预置。

完全没有 `dataPlane`、`instanceId`、`initializationSource` 三个 marker 的历史**模拟**状态，可在首次本地模拟启动时做一次仅补 marker 的兼容迁移；含有任一错误或半迁移 marker 的状态一律拒绝。`live` 永不接受无 marker 的状态。

## 生产配置矩阵

完整的无密钥模板见 [apps/api/.env.production.example](../apps/api/.env.production.example)。真实密钥必须由服务管理器、系统密钥库或云密钥服务注入；不要把它们写入 Git、普通 `.env`、截图、Figma 或工单正文。真实平面的后台系统设置默认只读，不能把部署/KMS 配置回写到共享的 `apps/api/.env`；只有部署层显式注入受控写入适配器时才允许受控变更。

### 网络与运行边界

| 配置项 | 用途与来源 |
| --- | --- |
| `PORT`、`API_HOST` | API 监听参数；生产固定绑定 `127.0.0.1`，仅允许同机反向代理接入。 |
| `TRUST_PROXY_HOPS` | 仅当同机反向代理层数固定且受信任时设置；启用后服务会拒绝非回环 `API_HOST`。 |
| `PUBLIC_BASE_URL` | API 对外 HTTPS 根地址；支付回调必须与它同源。 |
| `CORS_ORIGINS` | 允许访问 API 的前端 HTTPS Origin，以英文逗号分隔且不带路径。 |
| `VM_DATA_PLANE`、`VM_DATA_ROOT`、`VM_DATA_PLANE_ID`、`VM_PLATFORM_TENANT_NAME` | 上述数据平面与当前实例租户边界，必须由受控部署环境固定；不可作为在线可热改配置。 |
| `WEB_CONCURRENCY`、`API_INSTANCE_COUNT` | JSON 账本阶段必须均为 `1`；`NODE_APP_INSTANCE` 只能为空或 `0`。 |
| `BUSINESS_TIMEZONE_OFFSET_HOURS`、`BUSINESS_DAY_START_HOUR` | 业务日计算；必须在上线前由运营确认。 |
| `DATABASE_URL` | 当前不是业务主数据源，只用于 PostgreSQL 迁移预备；不能因配置它而认为系统已切换到数据库。 |

### 真实短信：阿里云号码认证 PNVS

旧实现调用的是阿里云资质管理员手机号校验接口，不能用于用户登录、注册或密码重置。本项目现改为 PNVS `SendSmsVerifyCode` / `CheckSmsVerifyCode`：发送端不返回验证码，服务端仍保留本地一次性、过期、失败次数和用途隔离状态。

| 配置项 | 获取方式 / 约束 |
| --- | --- |
| `VERIFICATION_CODE_PROVIDER` | 真实平面可设 `aliyun_pnvs` 或 `manual`；`manual` 只接受后台为当前实例已启用账号签发的 6 位短期一次性验证码。模拟平面标准模式固定 `mock`。 |
| `ALIYUN_PNVS_ACCESS_KEY_ID`、`ALIYUN_PNVS_ACCESS_KEY_SECRET` | 阿里云 RAM 创建最小权限服务账号；仅授予号码认证短信所需权限。 |
| `ALIYUN_PNVS_REGION_ID` | 通常 `cn-hangzhou`。 |
| `ALIYUN_PNVS_ENDPOINT` | 通常官方 `dypnsapi.aliyuncs.com`。 |
| `ALIYUN_PNVS_SIGN_NAME` | 在号码认证控制台创建并审核的系统签名。 |
| `ALIYUN_PNVS_TEMPLATE_CODE` | 已审核验证码模板；模板参数必须含 `##code##`。 |
| `ALIYUN_PNVS_SCHEME_NAME_APP_LOGIN` | 可选；留空使用默认方案，填写时仅 `app-login` 使用。 |
| `ALIYUN_PNVS_SCHEME_NAME_REGISTER` | 可选；留空使用默认方案，填写时仅 `register` 使用。 |
| `ALIYUN_PNVS_SCHEME_NAME_GENERAL` | 可选；留空使用默认方案，填写时仅 `general` 使用。 |
| `ALIYUN_PNVS_SCHEME_NAME_PASSWORD_RESET` | 可选；留空使用默认方案，填写时仅 `password-reset` 使用。 |
| `VERIFICATION_CODE_PREVIEW_ENABLED` | 真实平面必须 `false`。 |

同一用途的发送和核验必须同时留空以使用默认方案，或使用同一个显式 `SchemeName`；显式配置时不同用途不得共用。首次配置、控制台开通和测试手机号限制见阿里云[短信认证服务说明](https://help.aliyun.com/zh/pnvs/user-guide/sms-authentication-service/)、[新手指引](https://help.aliyun.com/zh/pnvs/getting-started/sms-authentication-service-novice-guide)、[发送 API](https://help.aliyun.com/en/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode) 与[核验 API](https://help.aliyun.com/en/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)。

### 微信支付

真实链路为小程序 `code` 换 `openid`、JSAPI 下单、客户端调起、验签回调、主动对账；退款还要处理退款回调和主动查询。API v3 没有独立沙箱，mock 不能替代渠道验收。

| 配置项 | 获取方式 / 约束 |
| --- | --- |
| `WECHAT_PAY_APP_ID`、`WECHAT_MINI_APP_SECRET` | 微信小程序后台的 AppID/Secret；Secret 仅服务端保存。 |
| `WECHAT_PAY_MCH_ID` | 微信支付商户平台的商户号；必须在商户平台绑定上述 AppID。 |
| `WECHAT_PAY_API_V3_KEY` | 商户平台“账户中心 → API 安全”由超级管理员设置的 32 位 APIv3 密钥。 |
| `WECHAT_PAY_MERCHANT_PRIVATE_KEY` | 申请商户 API 证书时生成并由商户安全保存的私钥。 |
| `WECHAT_PAY_MERCHANT_CERT_SERIAL_NO` | 对应商户 API 证书序列号。 |
| `WECHAT_PAY_PLATFORM_PUBLIC_KEY`、`WECHAT_PAY_PLATFORM_CERT_SERIAL_NO` | 从微信支付平台下载的公钥/证书材料及匹配标识。 |
| `WECHAT_MINI_LOGIN_URL` | 可留空使用官方默认；若填写只能是 `https://api.weixin.qq.com/sns/jscode2session`。 |
| `WECHAT_PAY_API_BASE_URL` | 可留空使用官方默认；若填写只能是 `https://api.mch.weixin.qq.com` 或官方允许地址。 |
| `WECHAT_PAY_NOTIFY_URL` | `PUBLIC_BASE_URL` 同源的 HTTPS `/api/payments/callbacks/wechat`，不得带查询参数。 |
| `WECHAT_PAY_REFUND_NOTIFY_URL` | `PUBLIC_BASE_URL` 同源的 HTTPS `/api/payments/callbacks/wechat-refund`，不得带查询参数。 |

参考微信支付[JSAPI/小程序下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791897)、[支付回调](https://pay.wechatpay.cn/doc/v3/merchant/4012791902)、[退款流程](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)、[退款回调](https://pay.wechatpay.cn/doc/v3/merchant/4012791906)、[APIv3 密钥](https://pay.wechatpay.cn/doc/v3/merchant/4012072195)、[商户 API 证书](https://pay.wechatpay.cn/doc/v3/partner/4012081992) 和 [AppID 绑定](https://pay.wechatpay.cn/doc/v3/merchant/4013289251)。

### 支付宝

项目采用 `alipay.system.oauth.token`、`alipay.trade.create`（`JSAPI_PAY`）、回调、查询、`alipay.trade.refund` 和退款查询。当前为普通公钥模式；若以后改证书模式，代码与配置需一起调整。

| 配置项 | 获取方式 / 约束 |
| --- | --- |
| `ALIPAY_APP_ID` | 登录支付宝开放平台创建应用、开通所需支付能力并审核上线后取得。 |
| `ALIPAY_SELLER_ID` | 实际收款商户的支付宝用户 ID，不是登录用户名。 |
| `ALIPAY_APP_PRIVATE_KEY` | 本地生成、仅服务端保管的应用私钥；向平台上传对应应用公钥。 |
| `ALIPAY_PUBLIC_KEY` | 从开放平台下载的支付宝公钥。 |
| `ALIPAY_GATEWAY_URL` | 可留空使用默认；生产若填写只能是 `https://openapi.alipay.com/gateway.do`。 |
| `ALIPAY_NOTIFY_URL` | `PUBLIC_BASE_URL` 同源的 HTTPS `/api/payments/callbacks/alipay`，不得带查询参数。 |

支付宝退款接口不单独配置 `ALIPAY_REFUND_NOTIFY_URL`；退款异步通知使用原支付接口的通知地址。参考[开放平台应用入口](https://open.alipay.com/module/webApp)、[密钥配置](https://opendocs.alipay.com/common/02kdnc)、[异步通知验签](https://opendocs.alipay.com/open/200/106120)、[退款 API](https://opendocs.alipay.com/open/6c0cdd7d_alipay.trade.refund) 和[小程序支付](https://opendocs.alipay.com/mini/api/openapi-pay)。沙箱的 AppID、网关和密钥材料必须与生产完全分离。

### SmartVM / 映翰通柜机平台

| 配置项 | 获取方式 / 约束 |
| --- | --- |
| `SMARTVM_MODE` | 新实例尚未录入柜机时设为 `disabled`，并保持地址、来源和凭据为空；录入首台柜机前改为 `real`。 |
| `SMARTVM_BASE_URL` | 必须由映翰通项目/售后提供的生产 HTTPS 地址；不得使用 `pre.smartvm.cn`。 |
| `SMARTVM_CLIENT_ID`、`SMARTVM_KEY` | 供应商分配的真实租户凭据，仅由密钥管理器保存。 |
| `SMARTVM_ALLOWED_NOTIFY_ORIGINS` | 供应商提供的精确 HTTPS Origin，英文逗号分隔；不能填路径或通配符。 |
| `SMARTVM_ALLOW_UNSIGNED_CALLBACKS`、`ALLOW_UNSIGNED_SMARTVM_CALLBACKS` | `live` 必须为 `false`；后者仅为旧兼容名，不应再配置。 |
| `SMARTVM_AUTO_FORWARD_SETTLEMENT_PAYMENT_SUCCESS` | `live` 必须 `false`；正金额订单只能由已确认支付单驱动。 |
| `SMARTVM_*_CALLBACK_PATH`、`SMARTVM_PAYMENT_SUCCESS_PATH` | 站内绝对路径；不得使用外部 URL、查询参数或片段。 |
| `SMARTVM_CALLBACK_MAX_AGE_SECONDS`、`SMARTVM_CALLBACK_FUTURE_TOLERANCE_SECONDS`、`SMARTVM_CALLBACK_EVENT_MAX_AGE_SECONDS` | 回调重放/时效边界；上线前与供应商时钟和重试策略一起确认。 |
| `SMARTVM_TIMEOUT_MS`、`SMARTVM_STATUS_STALE_AFTER_MS`、`SMARTVM_OPEN_COMMAND_LEASE_MS` | 设备网络超时、状态过期和开门互斥窗口。 |

真实接通前必须由供应商书面提供生产 endpoint、租户凭据、生产设备/门清单、回调注册步骤、签名样例、错误码、重放规则、允许来源/IP、密钥轮换方式和受控测试柜授权。公开产品页见[映翰通智能新零售系统](https://www.inhand.com.cn/products/smart-vending-system/)与[InVending 云平台](https://www.inhand.com.cn/products/invending-cloud/)。

### 支付账本与对账

| 配置项 | 真实入口要求 |
| --- | --- |
| `PAYMENT_MODE` | 即时领取固定 `real`；预约取货且 `VM_RESERVATION_ONLY_PICKUP=true` 时可设 `disabled`。`auto`/`mock` 仅模拟平面。 |
| `PAYMENT_MOCK_ENABLED` | 兼容旧项；真实入口不能为 true。 |
| `PAYMENT_PROVIDER_TIMEOUT_MS` | 渠道 HTTP 超时；上线前按渠道 SLA 确认。 |
| `FINANCIAL_SINGLE_WRITER_ENABLED` | 必须 `true`。 |
| `FINANCIAL_INSTANCE_ID` | 金融写入者实例标识；由部署系统提供。 |
| `FINANCIAL_SINGLE_WRITER_LEASE_MS`、`FINANCIAL_SINGLE_WRITER_HEARTBEAT_MS` | 账本单写者租约参数；真实平面租约文件由 `VM_DATA_ROOT` 派生。 |
| `PAYMENT_RECONCILIATION_ENABLED` | 必须 `true`。 |
| `PAYMENT_RECONCILIATION_INTERVAL_MS`、`INITIAL_DELAY_MS`、`MAX_DELAY_MS`、`BATCH_SIZE`、`ALERT_AFTER_ATTEMPTS`、`USER_REQUEST_COOLDOWN_MS` | 真实支付/退款待确认状态的自动对账与告警阈值。 |

| `PAYMENT_PAYER_IDENTITY_TTL_SECONDS`、`PAYMENT_PAYER_IDENTITY_HANDLE_CAPACITY` | 服务端付款人身份句柄的有效期与容量。 |

## 上线前必过清单

1. 独立创建真实数据根、稳定 `VM_DATA_PLANE_ID`、`VM_PLATFORM_TENANT_NAME` 和受控 `PUBLIC_BASE_URL`，不复制模拟状态、审计、上传或备份。
2. 通过受控初始化创建首个非默认服务商和首管理员，或仅迁入两个已改密账号的密码散列；不得保留其他测试账号或旧管理员凭据。
3. 选择人工码时验证后台签发、失败计数、撤销、过期和单次消费；选择 PNVS 时才要求签名、模板和用途方案全部审核并完成受控短信验证。
4. 预约取货关闭支付时确认支付/退款账本为空；选择真实收款时才要求微信、支付宝渠道全部完成审核和最小金额对账测试。
5. 映翰通提供生产凭据、回调规范与测试柜授权；在不影响其他柜机的授权设备上完成开门、结算、退款和重放测试。
6. 在目标 Linux 主机验证运行目录 ACL、POSIX 持久化、单写者、备份、恢复、跨平面恢复拒绝和 `/api/health/production-readiness`。
7. 按 [发布与公网部署验证流程](发布与公网部署验证流程.md) 先本地验证、再提交推送、再由服务器 Git 拉取和公网 URL 复验；不得直接修改生产代码。
