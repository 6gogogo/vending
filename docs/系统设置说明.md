# 系统设置说明

本说明面向实例管理员。页面先展示日常可操作的“示例设置”；其余项属于发布或服务对接资料，默认折叠为“查看部署说明”。不要把密码、验证码、密钥或服务商私有资料写进截图、工单或本说明。

## 1. 日常验收只改三项

| 设置 | 推荐值 | 什么时候改 | 结果 |
| --- | --- | --- | --- |
| 预约取货 | 开启 | 当前预约制验收 | 用户先预约再取货；新的领取流程不创建支付单，也不需要支付配置。 |
| 领取差异的额度归属 | 自动 | 需要核对预约数量和实际领取数量不一致时 | 可选择自动、原领取时间、预约创建时间或柜机回传时间；默认自动。 |
| App 登录验证方式 | 手动设置验证码 | 进行 App / 小程序验收时 | 实例管理员为已启用测试人员签发 6 位、短期、一次性的人工码；不会发送短信。 |

关闭“预约取货”才会显示非预约领取和支付相关设置。这样做只用于隔离测试，不会修改历史订单，也不表示已经接入真实收款。

“预约取货”与人员管理中的预约规则是两个前置条件：前者决定领取流程是否走预约和是否隐藏支付步骤，后者决定 App 是否允许提前预约。当前预约验收需要两者都开启；测试人员还必须有当天有效的物资模板或个人领取规则，并且柜内存在有效库存。

### 领取差异额度归属的四种选择

| 选项 | 结果 |
| --- | --- |
| 自动：有预约按预约日，无预约按领取日 | 默认选择；分别按各流程的业务日期归属。 |
| 按原领取时间计入额度 | 统一按本次领取业务创建时间归属。 |
| 按预约创建时间计入额度 | 统一按预约生成时间归属。 |
| 按柜机回传时间计入额度 | 统一按柜机实际回传到平台的时间归属。 |

## 2. 运行方式：只选择，不手填

`Node 运行环境` 与 `应用运行环境` 都是下拉框：`development`、`test`、`production`。它们不对应物资、预约或人员模板，不应为了匹配某个模板手填；日常验收按发布状态选择，两项通常保持一致。

- `development`：本地开发或普通模拟。
- `test`：自动化测试。
- `production`：公网发布流程固定的运行态。页面会只读显示，不能在后台改写。

数据平面只有“模拟”和“实机”两类。`mock`、阿里云 PNVS 与人工验证码只是验证实现，不会增加第三种运营环境。

## 3. 哪些设置需要谁来处理

| 类别 | 谁处理 | 实例管理员要做什么 |
| --- | --- | --- |
| 示例设置 | 实例管理员 | 预约制、额度归属、App 验证方式按当前验收目标选择。 |
| 运行方式、数据目录与实例名称 | 发布人员 | 只确认当前值；数据、审计、上传、备份和实例身份始终不能在线修改。 |
| 短信、地图、柜机、模型服务 | 对接人员 | 根据服务商资料填写；未做接入时保持当前值。 |
| 支付 | 财务/对接人员 | 预约取货开启时无需填写；关闭预约后才做隔离验证。 |
| 一致性与服务数量 | 发布人员 | 保持当前值，避免账目或服务状态冲突。 |

所有字段旁边的状态含义一致：`保存即生效` 表示下一次业务请求使用新值；`重启后生效` 表示保存后需要由发布流程重启 API。敏感项始终遮挡，只有有权账号才可显示或编辑。

## 4. App 手动验证码验收

1. 后台“人员管理”创建并启用一个特殊群体测试人员；后台显式建档后即为已审核账号。
2. 为该人员绑定当日可领取物资模板，或新增一条个人领取规则；它要覆盖当前时间和至少一种有库存物资。
3. 确认预约规则已开启，并在该人员行选择“签发人工码”，用途选“APP / 小程序登录”。
4. 在受控签发面板内生成或输入本次 6 位验证码，设置 60–600 秒有效期并签发。
5. 在 App 手机登录页填写测试人员手机号和人工码，勾选免责声明后登录。
6. 在 App 选柜、选物资并提交预约；确认保留时间和物资清单。仅在获得柜机操作授权时，继续使用“用预约开柜”并核对“预约取货完成”或“领取待核对”。
7. 首次登录成功后，后台记录应为“已使用”；同一验证码再次登录必须被拒绝。

人工码只适用于当前实例、已启用的既有账号；不能自动建号、不能跨实例、不能代替电脑后台管理员密码。未建档人员应走公开注册与审核流程，人工码不能绕过该边界。

## 5. 角色权限速查

| 角色 | 主要操作 | 不应执行的操作 |
| --- | --- | --- |
| 服务提供商 | 平台范围创建、查看、进入或退出实例，查看平台级审计。 | 未进入实例时直接处理实例业务。 |
| 实例管理员 | 当前实例的人员、账号、人工码、柜机、库存、规则、日志和已授权设置。 | 创建或切换其他客户实例，查看其他实例或原始服务密钥。 |
| 商户 | 自己的货品投放、补货模板和业务去向。 | 其他商户、其他实例或未分配柜机。 |
| 补货员 | 已分配柜机的补货与现场处理。 | 人员、账号、人工码、系统设置和未分配柜机。 |
| 特殊群体用户 | App / 小程序登记、预约取货和记录查看。 | 电脑后台和他人业务资料。 |

角色新建、柜机分配与复核步骤见[实例后台使用手册](实例后台使用手册.md)。

## 7. 常见情况与处理

| 看到的情况 | 正确处理 |
| --- | --- |
| 人工码登录失败 | 确认人员已启用且属于当前实例；过期、撤销、锁定或已使用的码必须重新签发。 |
| 登录成功却不能预约 | 同时检查预约取货、人员预约规则、当前时段领取策略和柜机库存。 |
| 找不到“获取验证码” | 手动人工码模式下不发送短信，这是预期界面。 |
| 预约流程不显示支付配置 | 预约取货开启时不需要支付配置，这是预期界面。 |
| 同一人工码被再次拒绝 | 这是一次性验证码的正常保护，旧码不能恢复。 |
