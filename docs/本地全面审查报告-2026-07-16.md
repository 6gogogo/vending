## 已完成的主要重构

### 认证、权限与自锁保护

- 会话和资料草稿改为高熵 token，并增加服务端过期、用户停用/角色变化、后台凭证变化后的失效检查。
- 密码修改、管理员重置密码、停用用户和退出登录会撤销对应旧会话。
- 验证码按用途隔离，成功后立即消费，失败次数与重发冷却受限；验证码和 token 不再进入业务快照。
- 生产判定同时考虑 `NODE_ENV` 与 `APP_ENV`，避免配置组合绕过严格门禁。
- 移动管理员人员更新、批量更新和库存调整改为白名单 DTO，拒绝角色、额度、价格、业务对象和未知字段越权写入。
- 服务端统一禁止管理员停用自己或修改自己的角色；单笔和批量请求都会在任何写入前失败，测试确认零副作用。
- PC 与移动端同步锁定当前账号的角色、状态和批量选择入口；移动端以“本人”标识，避免误操作和拥挤换行。
- 后台会话每次鉴权重新绑定当前凭证；非默认租户在当前单实例模型下 fail-closed，不伪装为已完成多租户隔离。

### 报价、支付、退款和幂等

- 开柜价格、免费额度、应付金额和支付方式改由服务端报价与结算决定；客户端不能再提交 `unitPrice` 或 `payStyle` 改写结果。
- 报价具备有效期、上下文绑定和幂等约束；库存、额度或价格漂移时要求重新确认。
- 创建支付单、支付回调、退款、退款回调和 SmartVM 付款回写增加单向状态与重放检查。
- 部分退款、累计全额退款、处理中余额占用、超额退款和并发退款均有覆盖。
- 微信与支付宝已补齐主动查单、未支付关单和退款查询；渠道返回未知状态时不直接改写业务终态。
- 退款请求必须显式提供金额和稳定退款号，同一退款号会绑定原订单、金额和原因；页面刷新后从服务端恢复待确认退款摘要，只能继续核对原退款单，不能新建第二笔退款。
- PC 后台区分“支付渠道原交易号”和“系统退款请求单号”；后者只读，用作本次请求幂等标识，不再冒充渠道退款号。
- 付款与退款使用两步复核，锁定服务端金额；`Ctrl + Enter` 在整个退款对话框内可继续。

### 柜机、开门和未知结果

- 柜机就绪度统一由服务端派生为 `online / stale / offline`；过期心跳不再被界面显示为可开门。
- 用户开柜与后台远程开门共用“设备 + 货门”级互斥和活动事件租约；同门并发冲突，不同货门可并行。
- 物理门不是明确关闭、设备状态未知或监控读取失败时，前后端均 fail-closed，拒绝开门并给出刷新/反馈路径。
- “等待确认”和“正在下发”改为独立状态；忙碌期阻止重复弹窗、重复请求、切换类型和离开流程。
- 408、409、5xx、网络中断、非 JSON 响应和平台回执不确定统一归为“结果未知”，禁止重复开门，只允许查看最新状态或反馈。
- PC 远程开门未知结果会锁定再次提交，刷新最新状态，并把 `Failed to fetch` 等底层错误转换为可执行中文提示。
- 明确平台拒绝仍可安全修改后重试；不确定结果不会被误判为明确失败。

### 库存、批次和预约

- 用户可领取库存排除过期批次；`expiresAt == now` 也视为不可领取。
- 预约、预结算、开柜和正常调拨均在服务端拒绝过期库存；拒绝时不会调用设备网关。
- 自动 FEFO 只使用有效批次，并按绝对时间排序；指定过期批次不会静默回退。
- 负库存优先抵扣后来补入的有效库存，避免高估可领取数量。
- 预约只锁定货品种类和数量，不锁定当前批次；开门时从仍有效批次分配。
- 正常调拨校验与扣减共用同一时间快照，避免跨到期瞬间的 TOCTOU。
- 过期批次使用独立处置闭环：精确批次、数量、原因、方式、不可逆确认、审计和持久化幂等。
- 盘点要求完整、非重复、非负整数明细；后续失败会回滚库存、记录和日志。

### 输入、隐私、存储与外部请求

- 路由和服务层补齐手机号、字符串长度、整数、批次、来源和完整盘点等边界。
- HTML-XLS 导出同时阻止 HTML 与公式注入，文件名安全化。
- 上传只接受结构完整、尺寸合理的静态图片，备份校验会拒绝缺失上传文件。
- 通用 HTTP、SmartVM、支付和 AI 上游请求增加明确超时与响应体上限。
- AI 和付款回写 URL 默认只允许明确目标，拒绝本地/保留地址和非允许来源。
- 审计入口统一脱敏签名、会话、手机号和 URL 查询参数；外发 AI 的日志、服务情况和错误摘要做隐私缩减。
- 安全响应头实测包含 `no-store`、`nosniff`、`DENY`、`no-referrer`，并禁用页面摄像头、麦克风和地理位置权限。

### 前端可靠性、视觉与可访问性

- 错误态不再伪装成空列表或 0 条数据；柜机、审核、首页、监控和运营开门均提供持续错误与恢复路径。
- PC 后台统一网络/解析错误中文化，不再向用户泄露 `Failed to fetch`、`NetworkError` 或 JSON 解析原文；明确业务错误保持原意。
- 免责声明使用 HTML `<dialog>` 模态语义、焦点约束和“读到末尾才可同意”的真实门槛。
- 远程开门、支付、退款、调拨、盘点、处置和批量停用均补齐两步确认或明确后果。
- 开柜确认显示柜机、编号、货门、距离未确认风险、免费/付费件数与金额；长字段和长文案不再越界裁切。
- 720×500 下退款与远程开门弹窗无横向溢出，内部滚动后最终动作仍位于可达视口。
- 关怀版保留资格、柜机状态、预约规则、距离提示、库存、价格、数量和反馈，不以“简化”为由隐藏关键安全信息。
- H5 tabbar 图片补齐文本替代；最终缺失图片文本为 0。
- 操作日志状态中文化，主要用户文案统一使用“物资/特殊群体”；仍有少量历史“商品”字段属于后续术语维护债务。
