# 全真模拟模式

## 结论

全真模拟是 `VM_DATA_PLANE=simulation` 下的隔离联调档，不是生产平面的降级版。它保留模拟业务数据、测试账号、模拟柜机记录和本地审计，但可以让柜机平台、支付、短信验证码、AI、地图分别选用 `mock` 或 `real`。默认所有模块仍是 `mock`，切换到 `real` 后不会自动回退到模拟通道。

全真模拟绝不会读取或写入 `live` 数据根。启用它必须配置独立的 `VM_DATA_ROOT` 和 `VM_DATA_PLANE_ID`；状态文件、上传、审计日志、备份和金融租约都从该根目录派生。

## 启用

在 `apps/api/.env`（或受控本地启动配置）中设置以下无密钥基础项。首次启用前请先停止本地 API；不能通过后台页面在运行中切换数据根或实例标识。

```dotenv
NODE_ENV=development
APP_ENV=development
VM_DATA_PLANE=simulation
VM_SIMULATION_PROFILE=full
VM_FULL_SIMULATION_ENABLED=true
VM_DATA_ROOT=runtime-data/full-simulation-local
VM_DATA_PLANE_ID=full-simulation-local-001

VM_FULL_SIMULATION_SMARTVM_MODE=mock
VM_FULL_SIMULATION_PAYMENT_MODE=mock
VM_FULL_SIMULATION_VERIFICATION_MODE=mock
VM_FULL_SIMULATION_AI_MODE=mock
VM_FULL_SIMULATION_MAP_MODE=mock
```

随后用独立数据根初始化测试数据，再启动 API：

```powershell
npm run init:api-data -- --confirm-reset
npm run dev:api
```

`init:api-data` 只会在目标数据根为空时写入测试种子；它不会覆盖日常模拟或真实平面的数据。

## 模块开关

| 模块 | 开关 | `mock` 行为 | `real` 行为与必要配置 |
| --- | --- | --- | --- |
| 柜机平台 | `VM_FULL_SIMULATION_SMARTVM_MODE` | 内存 SmartVM，不发网络请求 | 使用 `SMARTVM_BASE_URL`、`SMARTVM_CLIENT_ID`、`SMARTVM_KEY`；缺任一项拒绝启动 |
| 支付 | `VM_FULL_SIMULATION_PAYMENT_MODE` | 本地模拟支付 | 严格走微信/支付宝真实下单；渠道配置不完整会直接报错，不会回退 |
| 短信验证码 | `VM_FULL_SIMULATION_VERIFICATION_MODE` | 本地验证码 | 使用阿里云 PNVS；缺少 PNVS 配置时请求验证码会失败，不发送模拟码 |
| AI | `VM_FULL_SIMULATION_AI_MODE` | 本地稳定兜底结果，不外发业务上下文 | 调用 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 与 `OPENAI_MODEL` 指定的兼容服务 |
| 地图 | `VM_FULL_SIMULATION_MAP_MODE` | 不加载高德脚本，可在后台地图选点器手工输入经纬度 | 向前端提供 `AMAP_WEB_KEY` 与 `AMAP_SECURITY_JS_CODE`，加载真实高德地图 |

各模块开关可在后台“系统设置”中按“全真模拟：柜机平台 / 支付 / 短信验证码 / AI / 地图”字段修改。保存后会明确标记为“需要重启”；重启 API 前旧进程仍保持旧配置。真实密钥仅通过本机受控配置或密钥管理方式提供，不要写进文档、命令行、日志或聊天记录。

## 人工码 App 预约基线

当同时满足以下条件时，API 启动会检查是否已有可预约的在线库存：

- 当前平面是隔离的 `simulation`，且已启用 `full`；
- 柜机平台与支付均为 `mock`；
- 短信验证码模式为 `manual`。

如果没有可预约库存，系统只会补建一台固定的模拟预约体验柜及最小食品库存，用于 App 人工码登录和预约闭环。已有可预约库存不会被覆盖；该基线不会在标准模拟、任何真实数据平面、真实柜机、真实支付或真实验证码通道中创建。体验柜没有通用写入入口，库存只属于隔离模拟数据根；在这一受控组合中，API 进程会为固定体验柜提供本地模拟心跳，避免等待页面操作时被误判离线。该组合下柜机列表展示的候选数量也会扣除过期批次和有效预约，保证验收运行器与实际预约校验选择同一商品。

## 边界

- `VM_SIMULATION_PROFILE=standard` 保持原有行为：全部外部模块均为模拟，真实凭据和真实外部调用会被拒绝。
- `VM_DATA_PLANE=live` 保持生产门禁：必须是 production，且全部真实配置由受控部署系统提供；全真模拟开关不生效。
- 全真模拟中的 `real` 代表真实外部副作用：可能开真实柜门、发送真实短信、产生真实支付或外发业务上下文。首次联调应一次只启用一个模块，并确认回调地址、测试账号及授权范围。
