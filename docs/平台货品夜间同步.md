# 平台货品同步

货品总览的「同步平台货品」会查询当前实例全部柜机及各柜门，然后按商品身份汇总。当前 SmartVM 1.1 的 `getCabinetGoodsInfo` 必须传入 `deviceCode`，双门柜还需 `doorNum`；没有接入平台全库查询接口。因此，仅存在于平台商品库、尚未关联任何本实例柜机的货品，不在同步范围内。

每天北京时间 23:00 自动执行一次。23 点这一小时内服务恢复且当晚尚未执行时，会补执行；错过整段时间不在白天补跑，可手动同步。每次执行重新读取柜机配置，新增柜机无需另配计划。一次任务失败或服务中断后，当晚不自动重复；管理员可查看失败柜门并手动重试。任务进度和当晚执行日期保存在操作日志中，进程重启后仍有效。

同步更新平台编号对应商品的名称、价格和图片。同编号改名更新原商品；默认跟随商品名称的全名也会更新，单独维护的详细全名保留。已有同名商品继续沿用项目的身份归并规则。平台删除再新建导致编号、名称同时变化时，不能保证自动识别为同一商品，应核对后处理。

本地分类、批次库存和领取规则保留。平台返回空列表不会删除本地货品。单个柜门失败会回滚该柜门本轮修改，其他柜门继续执行。手动单柜同步与全柜同步共享串行查询队列，避免较旧结果晚到覆盖新资料。页面显示成功柜门数、去重货品数和失败明细。

手动同步需要 `goods:manage` 后台权限；查看结果需要 `goods:view`。后台任务只在持有运行数据写租约、生产数据与审计就绪时执行，每次异步查询返回后重新检查。任务只查询商品资料，不发出开门或库存回写指令。
