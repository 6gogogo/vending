# 公益智助柜公网使用与验收手册

本文档面向服务提供商、实例管理员、商户、补货员和 App 用户，说明当前公网模拟环境的使用顺序、权限边界与验收记录方式。

它是后续公开 `/guide` 页面和 App 帮助中心的内容来源之一。当前仓库中的 Markdown 文档本身不等同于已发布的公开页面；只有实际发布并从公网访问后，才能作为公网交付物使用。

## 1. 使用范围与入口

当前产品只有两种运行方式：模拟服务与实机服务。短信 mock、阿里云 PNVS 和后台签发人工码是不同的验证实现，不是第三种运行方式。

| 用途 | 入口 | 说明 |
| --- | --- | --- |
| 电脑后台 | `https://vending.5gogogo.top/login` | 服务提供商、实例管理员、商户和补货员使用账号密码登录。 |
| 移动 App / H5 | `https://vending.5gogogo.top/mobile/` | 特殊群体用户进行身份识别、预约和查看记录；商户与管理员的移动入口按角色展示。 |
| 健康检查 | `https://vending.5gogogo.top/api/health` | 仅用于发布验收的连通性检查，不用于日常业务操作。 |
| 带端口入口 | `http://5gogogo.top:5795/` | 仅是可选的无状态跳转入口；应返回 `308` 并跳转至上述 HTTPS 主站。 |

带端口入口不承载登录、验证码、Cookie、接口写入或业务路径。不要在其后拼接路径、查询参数或任何登录数据；所有登录和业务操作都在 HTTPS 主站完成。

## 2. 角色与权限边界

| 角色 | 主要工作 | 明确边界 |
| --- | --- | --- |
| 服务提供商 | 查看平台汇总、创建客户实例、进入或退出实例、查看平台级审计。 | 平台范围会话不能直接读取或修改任一实例的业务数据。 |
| 实例管理员 | 管理本实例的人员、后台账号、柜机分配、人工码、审核、库存、日志与已授权设置。 | 不能创建或切换其他客户实例，不能读取其他实例数据或原始服务密钥。 |
| 商户 | 维护自身货品、补货模板、补货和领取去向。 | 不能访问其他商户、其他实例或未分配柜机的数据。 |
| 补货员 | 查看并处理明确分配给自己的柜机。 | 不能管理人员、后台账号、人工码、系统设置或未分配柜机。 |
| 特殊群体用户 | 在 App / 小程序完成身份识别、预约取货和记录查看。 | 不进入电脑后台，不查看他人资料或业务记录。 |

权限由服务端会话和实例归属共同决定。只修改浏览器地址、请求参数或前端显示不能扩大权限。

## 3. 服务提供商：开通并进入客户实例

### 3.1 平台范围登录后先确认范围

1. 从电脑后台入口登录服务提供商账号。
2. 打开“服务商后台 → 全局工作台”，确认当前处于平台范围。
3. 平台范围只查看实例汇总、实例列表和平台级审计；不应出现可直接编辑实例业务数据的入口。

### 3.2 一次创建实例与首管理员

1. 在“全局工作台”打开“实例开通”。
2. 填写实例编码、实例名称、状态和必要的联系信息；实例地址与服务方案按实际需要填写。
3. 填写首管理员的姓名、手机号、后台登录账号和密码。密码只在本地受控输入框中输入，不写入截图、文档、聊天或命令。
4. 提交后确认提示“实例及首管理员已原子创建”，并确认页面不会再次显示密码。
5. 如果创建失败，停止重复提交并核对提示；一次失败不应留下半成品实例、人员或后台凭据。

### 3.3 进入和退出实例

1. 在实例列表选择目标实例并点击“进入实例”。
2. 进入后，系统应撤销旧的平台范围会话并签发绑定该实例的新会话。
3. 先检查左侧菜单只显示当前实例已开放的功能；新实例未完成租户化的旧模块应保持不可访问。
4. 完成实例内操作后点击“退出实例”。退出后系统再次轮换会话并回到平台范围。

服务提供商不得把“进入实例”当作跨实例浏览模式。每次进入只对应一个实例，退出后才能回到平台范围。

## 4. 实例管理员：先建人、再授权、后验收

### 4.1 人员、后台账号与柜机分配

推荐顺序如下：

1. 打开“人员管理”，创建并启用人员。
2. 选择与实际职责一致的身份：管理员、商户、补货员或特殊群体。
3. 对商户或补货员，先分配可管理柜机，再按最小权限开通后台账号。
4. 重新登录该角色账号，确认菜单、列表、详情和操作均只显示其职责范围。
5. 在“系统操作日志”核对人员创建、授权、分配和后续操作记录。

不要先创建一个有后台权限的空账号再补人员或柜机分配。人员归属、角色授权和柜机范围是同一条验收链路的前置条件。

### 4.2 预约取货和额度归属

在“系统设置 → 示例设置”中，实例管理员可以按业务需要调整领取方式和额度归属。

| 设置 | 选择后的行为 |
| --- | --- |
| 预约取货开启 | 用户先预约后取货；当前流程不创建支付单，也不需要填写支付配置。 |
| 预约取货关闭 | 系统进入即时领取流程；页面可能显示支付相关设置，但不等同于已经启用真实支付。 |
| 领取差异的额度归属 | 用于柜机实际领取数量与预约不一致时的统计归属。日常验收可使用页面推荐值，并按实际业务规则确认。 |
| App 登录验证方式 | 当前实例显示该项时，可确认是否采用后台签发人工码；未显示时由服务管理员维护。 |

开始预约验收前，应同时确认：预约取货已开启、人员预约规则已开启、用户已启用且有当日有效的领取规则、目标柜机在线并有可预约库存。

### 4.3 人工验证码：仅用于移动身份识别

人工码只适用于当前实例内已存在且已启用的账号，用于 App / 小程序登录或本人密码重置。它不是电脑后台密码，也不是永久码或全局固定码。

1. 在“人员管理”选择当前实例内已启用的目标人员。
2. 选择“签发人工码”，用途选择“App / 小程序登录”。
3. 使用页面提供的 6 位数字和有效期设置完成签发；只通过受控渠道交给目标人员。
4. 首次登录成功后，在人工码记录中确认状态已消费。
5. 对同一条码再次登录，必须被拒绝；过期、撤销、替换或达到失败上限的码也不能恢复使用。

签发、撤销和消费记录应可审计，但任何截图、日志导出或验收表都不得记录手机号或验证码明文。

## 5. 商户与补货员：用受限账号复核边界

### 商户

商户在自己的工作台维护货品投放、常用商品、补货登记和领取去向。验收时应确认其不能读取其他商户、其他实例或未分配柜机的数据。

### 补货员

补货员只处理分配给自己的柜机。验收时应分别检查柜机列表、柜机详情和现场操作预检；未分配柜机不得出现在列表中，也不得通过直达地址进入。

商户和补货员均不应看到人员管理、后台账号、人工码签发或系统设置。发现越权菜单或接口响应时，停止业务操作并记录页面、时间和最小复现步骤。

## 6. App 用户：人工码身份识别与预约取货

### 6.1 人工码模式下的建档方式

人工码模式不发送注册短信，也不提供自助注册验证码。未登记用户应查看“管理员建档指引”或联系工作人员，由实例管理员完成建档、资料审核和角色分配。

账号启用后，管理员签发一条一次性登录码。用户在 App 登录页填写手机号和 6 位验证码，勾选免责声明后完成身份识别。验证码已使用、已撤销、已过期或失败次数达到上限时，需重新由管理员签发。

### 6.2 预约取货流程

1. 登录后先查看当天资格、开放时段和可领取提示。
2. 进入在线柜机详情，选择货品和数量。
3. 点击“提交预约取货”，确认柜机、保留时间和物资清单。
4. 到达同一台柜机后，在“当前预约”核对内容。
5. 仅在已获得真实柜机操作授权、现场条件满足且不影响服务时，才使用“用预约开柜”。

当前预约制不需要支付配置，也不应出现要求用户付款的步骤。未获柜机操作授权时，App 验收应止于预约已创建和开柜前确认页，不操作真实柜机。

## 7. 推荐验收顺序

1. 从带端口入口访问，记录其是否只跳转到 HTTPS 主站。
2. 在 HTTPS 主站检查 `/login`、`/mobile/` 和健康检查的可达性。
3. 使用服务提供商会话完成“平台范围 → 创建实例 → 进入实例 → 退出实例”边界检查。
4. 使用实例管理员会话完成“人员 → 角色账号 → 柜机分配 → 人工码 → 审计记录”链路。
5. 分别用商户和补货员账号复核受限菜单、数据和柜机范围。
6. 由已建档的 App 用户完成“人工码登录 → 预约创建 → 当前预约 → 同码重放拒绝”。
7. 最后进行桌面和 390×844 手机视口的视觉检查，并将截图编号写入验收记录。

每个账号角色应使用独立会话完成检查。不要在一个已登录管理员会话中通过前端跳转替代其他角色验收。

## 10. 完成判定

只有下列条件同时满足，才能写“本轮公网使用与验收闭环完成”：

1. 已在实际 HTTPS 主站按本手册完成角色与入口检查。
2. 验收矩阵中每项都有对应的非敏感证据与日期。
3. 截图清单中与本次范围相关的项目均已重新采集，且手机与桌面页面无明显错位。
4. 人工码、预约和权限边界均有实际结果；不能用本地单元测试或旧截图替代。
5. 任何真实短信、支付或柜机操作均有单独授权；未授权时保留在安全的模拟或开柜前确认步骤。

在上述条件满足前，本手册只能作为操作和验收模板，不构成“线上认证流程已完成”的声明。
