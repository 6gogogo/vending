# 服务提供商 UI 前运维与实例开通手册

这份手册只说明服务提供商开始工作前需要检查什么，以及进入后台后可以做什么。密码、验证码、密钥和手机号不要发到聊天、截图或普通工单中。

## 1. 当前入口

- 电脑后台：<https://vending.5gogogo.top/login>
- 身份操作说明：<https://vending.5gogogo.top/guide>
- 带端口入口：<http://5gogogo.top:5795/>，会固定跳转到 HTTPS 主站。
- 当前服务商入口始终显示“正式服务商平台”。Spark 的运行数据平面只用于隔离数据和外部通道，不再作为服务商身份标签。
- 当前平台初始化账号：`super`。首次密码必须在 Spark 的 VNC 本机终端设置，不能由实例管理员创建或重置。

## 2. 首次进入 UI 前：只做一次

在 Spark 的 VNC 本机终端执行。不要通过 SSH、管道或命令参数传递密码。

```bash
cd /home/fivegogogo/vending/current
export PATH=/home/fivegogogo/.nvm/versions/node/v22.22.2/bin:/usr/bin:/bin
npm run preflight:first-super-admin-password:maintenance
npm run init:first-super-admin-password:maintenance
```

预检通过后，第二条命令才会在本机终端非回显地要求输入两次新密码。密码至少 8 位。成功标志是：

```text
服务商超级管理员首次密码维护完成，API 已恢复并通过本机健康检查。
```

该命令只允许默认状态下执行一次。设置成功后，再次执行会拒绝覆盖；日后知道当前密码时，直接在后台“修改密码”中更新。

## 3. 日常进入 UI 前：30 秒检查

```bash
systemctl --user is-active vending-api-candidate.service
systemctl --user is-active vending-public-web.service
curl -fsS http://127.0.0.1:8100/api/health
```

前两条应返回 `active`，健康接口应返回 HTTP 200。任一项失败时先停止业务操作，不要修改 `.env`、直接启动第二套进程或暴露 Spark 原始端口。

## 4. 服务提供商在 UI 中的权限

登录后进入“服务商后台 → 全局工作台”。

### 平台范围

- 查看客户实例和跨实例汇总。
- 一次创建客户实例、首管理员人员记录和首管理员后台账号。
- 维护实例名称、状态、地址、联系人和服务方案。
- 暂停实例。
- 进入一个指定实例。
- 查看平台级操作记录。

平台范围不能直接读取或修改某个实例的人员、柜机、库存和预约数据。

### 进入实例后

- 管理当前实例的人员、角色和后台账号。
- 为商户、补货员分配柜机。
- 管理柜机、货品、库存、预约和实例业务设置。
- 签发当前实例的一次性人工验证码。
- 为忘记密码的实例管理员代重置密码；必须填写原因，重置后旧会话立即失效。

完成后选择“退出当前实例”，再进入其他实例。服务提供商不能同时以一个会话混合操作多个实例。

### 不允许的操作

- 实例管理员、商户或补货员不能创建、授权或重置服务商账号。
- 服务提供商未进入实例时不能直接操作实例业务。
- UI 不能修改部署密钥、支付私钥、短信密钥、数据根或运行平面。
- 真实数据平面不能在线追加另一个客户实例。

## 5. 在 UI 中创建新实例

打开“全局工作台 → 实例开通”，准备：

| 字段 | 要求 |
| --- | --- |
| 实例编码 | 2 至 50 位小写字母、数字或连字符，创建后保持不变。 |
| 实例名称 | 客户或运营单位的正式名称。 |
| 服务类型 | “正式服务”用于真实运营，“模拟服务”用于演练。服务类型与试运行、运行中、暂停不是同一个概念。 |
| 状态 | 正式服务创建时显示“待开通”；模拟服务可选“演练中”或“运行中”。 |
| 实例地址 | 准备使用的 HTTPS 地址；尚未分配域名时可暂不填写。 |
| 联系人与手机号 | 运营联系人；手机号为选填，但生产接入前应补齐。 |
| 服务方案 | 例如“预约取货”“公益预约服务”。 |
| 首管理员姓名、手机号、账号 | 手机号和后台账号不能与现有人员重复。 |
| 首管理员首次密码 | 至少 12 位，由服务提供商在页面本地输入，只通过安全渠道交付。 |

选择“创建实例与首管理员”后，实例、人员和后台凭据会一起保存。任何一步失败都不会留下半个实例。正式实例在生产开通完成前，服务商不能进入，首管理员和移动端也不能借当前模拟入口登录。

当前平台已经有实例编码 `current`，新实例必须使用其他编码。“小柜大爱”应选择“正式服务”，再填写独立实例编码、入口和首管理员资料。

## 6. 正式服务开通

在 UI 选择“正式服务”会建立正式服务记录，但不会把模拟数据自动升级成生产数据。正式实例使用独立 `live` 数据平面，不能把现有模拟库直接改名或复制过去。

生产接入另建独立 `live` 数据平面，并在受管服务中固定：

- 独立数据根和稳定的数据平面 ID。
- 生产 HTTPS 域名与 CORS 来源。
- 非默认服务商账号。
- SmartVM 生产配置，以及 PNVS 或后台一次性人工码中的一种验证方式。
- 预约取货实例关闭支付；只有启用真实收款时才配置微信/支付宝和支付对账。
- 单写者、备份和审计目录。

“小柜大爱”固定为正式服务、预约取货、关闭支付、后台签发一次性人工验证码。其 `live` 库只迁入现有已改密的服务商和 `admin` 首管理员密码散列，不复制模拟业务数据；服务商平台标题仍为“正式服务商平台”。

生产数据根只能通过受控初始化创建，不能在 UI 中热切换。初始化和发布按[真实入口、外部凭据与数据平面配置说明](真实入口配置与数据平面说明.md)及[发布与公网部署验证流程](发布与公网部署验证流程.md)执行。

只有 `/api/health/production-readiness` 返回 HTTP 200，实例才显示为可正式运行。普通 `/api/health` 返回 200 只表示服务进程存活。
