# 公益智助柜用户使用手册

本手册按身份说明日常操作。密码、一次性验证码和用户联系方式不应出现在聊天、截图或公开工单中。

## 1. 入口与身份

| 使用者 | 入口 | 主要工作 |
| --- | --- | --- |
| 服务提供商 | [电脑后台登录](https://vending.5gogogo.top/login) | 维护、进入和切换已开通的客户实例。 |
| 实例管理员 | [电脑后台登录](https://vending.5gogogo.top/login) | 管理当前实例的人员、柜机、货品、预约和登录方式。 |
| 商户、补货员 | [电脑后台登录](https://vending.5gogogo.top/login) | 在管理员授权的柜机范围内完成货品、补货和巡检工作。 |
| App 用户 | [移动端入口](https://vending.5gogogo.top/mobile/) | 使用一次性验证码登录、预约并到柜领取。 |

带端口入口 `http://5gogogo.top:5795/` 只用于跳转，会自动进入 HTTPS 主站；登录和全部业务操作都在 HTTPS 主站完成。

## 2. 服务提供商

### 2.1 首个服务商账号与日常登录

首个服务商账号由平台初始化负责人通过受控初始化流程建立。实例管理员不能创建、重置或接管服务商账号。

```mermaid
flowchart LR
  A[平台初始化负责人] --> B[建立首个服务商账号]
  B --> C[服务商登录全局工作台]
  C --> D[维护或进入已开通实例]
  D --> E[进入目标实例处理业务]
  E --> F[退出当前实例并切换客户]
```

1. 从平台初始化负责人处通过安全渠道取得服务商登录账号。
2. 打开电脑后台登录页，输入服务商账号和密码。
3. 登录后进入“服务商后台 → 全局工作台”。
4. 知道当前密码时，可在左侧“修改密码”中自行更新密码。
5. 忘记服务商密码时，联系平台运维负责人按受控恢复流程处理；登录页的“忘记密码”只用于实例后台账号。
6. 服务商账号不属于任何客户实例，实例管理员无法修改该账号。

### 2.2 开通正式客户实例

当前正式平台按“一个正式实例对应一套独立数据平面”运行。新增正式实例时，服务提供商准备实例名称、固定编码、HTTPS 入口、联系人、服务方案和首管理员资料，由服务管理员完成独立数据根、域名、首管理员和生产门禁配置。开通完成后，实例会出现在全局工作台。

当前正式数据平面不能直接追加第二个客户实例。页面内创建实例只用于模拟控制面的演练数据，不能替代正式开通。

首次设置服务商账号或需要做上线前检查时，参照[服务提供商 UI 前运维与实例开通手册](服务提供商UI前运维与实例开通手册.md)。

### 2.3 维护和进入客户实例

在全局工作台的实例列表中：

1. 选择“维护实例”，可修改实例名称、运行状态、地址、联系人和服务方案。
2. 选择“暂停”后，服务商不能再次进入该实例；已有业务数据和操作记录会保留。
3. 选择“进入实例”后，后台菜单切换为该实例的人员、柜机、库存、预约和设置页面。
4. 完成当前实例工作后，选择左侧“退出当前实例”，再处理其他客户实例。

服务商在平台范围只能管理实例；只有进入某一个实例后，才可以查看或修改该实例的业务数据。

## 3. 实例管理员

实例管理员只处理当前实例，不创建或切换其他客户实例。

### 3.1 设置预约取货和额度规则

打开“系统设置 → 领取与服务设置”，先处理“实例设置”分组：

1. “预约取货”开启时，用户先预约再领取，页面不会要求支付配置。
2. “额度差额归属”用于柜机实际领取数量与预约数量不一致时的统计日期。一般选择“自动”；有明确业务规则时再选择对应日期方式。
3. “App 登录验证方式”选择“手动验证码”时，由实例管理员签发 6 位、一次性的登录验证码。

运行环境不是业务模板。它由发布方案管理，实例管理员不需要为预约、货品或人员手动填写运行环境。

“小柜大爱”当前为正式服务，采用预约取货、关闭支付、后台签发一次性人工验证码。尚未接入柜机时，App 可以完成登录和查看服务状态，但不会出现可预约柜机或可领取库存。

![正式实例的领取与服务设置](assets/backoffice-instance-settings-live-1440x900-20260730.jpg)

### 3.2 建人、授权和分配柜机

1. 打开“人员管理”，先创建或审核人员资料，再启用账号。
2. 为需要使用电脑后台的人员配置角色：实例管理员、商户或补货员。
3. 为商户和补货员分配可操作的柜机。未分配柜机不会出现在其列表中。
4. 在“柜机监控”确认目标柜机在线，并确认有可预约库存。

### 3.3 签发 App 人工验证码

1. 在人员管理中选中已启用的 App 用户。
2. 打开“人工验证码”，用途选择“APP / 小程序登录”。
3. 输入本次要交付的 6 位验证码，设置有效期后签发。
4. 通过安全方式把验证码交给该用户；首次成功登录后，原验证码不能再次使用。

人工验证码只服务于当前实例中已启用的既有账号，不能用于创建账号，也不能替代电脑后台密码。

### 3.4 修改或找回实例后台密码

知道当前密码时：

1. 登录电脑后台。
2. 在左侧选择“修改密码”。
3. 输入当前密码和新密码后保存；保存成功后使用新会话继续操作。

忘记密码时：

1. 在后台登录页选择“忘记密码”。
2. 输入后台登录账号和该人员资料中绑定的手机号。
3. 阿里云短信模式下选择“获取找回验证码”；人工码模式下，请同实例另一名管理员为本人签发用途为“后台密码重置”的验证码。
4. 输入验证码和两次新密码，选择“验证并重置密码”。
5. 重置成功后返回登录页。原有电脑和浏览器登录会话会全部失效。

如果唯一实例管理员无法取得找回验证码，由服务提供商在全局工作台进入该实例，在“人员管理”找到目标管理员并选择“代重置密码”。服务提供商需要填写原因，完成后目标账号旧会话同样失效。

初始 `admin` 账号可使用不少于 6 位的新密码；其他后台账号的新密码不少于 8 位。每个实例必须至少保留一名启用、已开通本实例后台凭据且可登录的实例管理员。

## 4. 商户与补货员

商户和补货员使用管理员开通的电脑后台账号登录。

- 商户维护授权柜机的货品、补货记录和领取去向。
- 补货员只处理被分配柜机的补货、巡检和现场任务。
- 每次提交后，在记录或日志中核对柜机、数量、时间和处理结果。
- 看不到其他柜机或其他客户的数据是正常的权限边界；需要扩大范围时联系当前实例管理员。

## 5. App 用户：登录、预约和领取

### 5.1 首次使用

未建档用户先联系当前实例管理员完成资料建档和启用。手动验证码模式不会发送短信，也不会自动创建账号。

![App 身份识别页](assets/app-public-login-390x844-20260729.png)

### 5.2 使用人工码登录

1. 打开移动端入口，选择已有账号登录。
2. 输入自己的手机号和管理员通过安全渠道交付的 6 位验证码。
3. 阅读并勾选页面提示后登录。
4. 登录后选择在线柜机与可预约货品，提交预约。

![App 人工验证码登录页](assets/app-public-manual-login-390x844-20260729.png)

### 5.3 到柜领取

1. 实例管理员先确认柜机已接入、在线，并已配置可预约库存和服务时段。
2. 在“当前预约”确认柜机、货品和保留时间。
3. 到达对应柜机后，按页面步骤完成领取。
4. 预约制不会要求支付；如页面出现付款步骤，先退出并联系实例管理员核对领取设置。

验证码过期、被撤销、输错次数达到上限或已经使用后，需要管理员重新签发。预约超时或柜机异常时，先查看当前预约状态，再向实例管理员反馈。

## 6. 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 不知道服务商账号如何创建 | 联系平台初始化负责人；实例管理员不能向上开通服务商账号。 |
| 服务商忘记后台密码 | 联系平台运维负责人按受控恢复流程处理；实例管理员和实例找回页都不能重置服务商账号。 |
| 需要新增正式客户实例 | 由服务管理员开通独立数据平面；当前正式实例内不能直接追加第二个客户。 |
| 服务商要修改实例信息 | 在“全局工作台”选择该实例的“维护实例”。 |
| 服务商要处理某个客户的业务 | 先在全局工作台选择“进入实例”，完成后选择“退出当前实例”。 |
| 实例管理员忘记后台密码 | 在登录页选择“忘记密码”自助找回；无法自助时由服务提供商进入该实例代重置。 |
| 实例管理员不需要支付配置 | 开启“预约取货”后，预约流程不创建支付单。 |
| App 用户不能登录 | 核对是否已启用、是否使用本实例签发的有效人工码；不满足时请管理员重新签发。 |
| 商户或补货员看不到柜机 | 请实例管理员检查后台角色和柜机分配。 |
