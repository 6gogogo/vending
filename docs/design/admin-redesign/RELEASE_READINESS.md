## 准备阶段记录的正式发布顺序

总门禁为 [发布与公网部署验证流程](../../发布与公网部署验证流程.md)，拓扑以 [Spark 公网最终入口链路](../../Spark公网最终入口链路.md) 为准。

1. **确认版本与窗口**：收到明确上线指令后，核对发布包 SHA256、候选提交、线上旧提交和干净状态。如果 `codex/UI` 或线上基线已经前进，先在开发分支整合并重新验证。完成物理手机抽查和已有依赖风险评审。后续开发继续留在当前功能分支。
2. **准备 Git 来源**：候选功能分支供评审；正式发布分支 `codex/UI` 的推进只在上线授权后进行。正常从 Git 拉取已批准的完整 SHA；如 GitHub TLS 再次失败，可使用本地已校验的增量 Git bundle，通过 Git 校验和快进拉取，不能复制源码覆盖。增量 bundle 要求服务器已有 `d9f3842…` 基线。
3. **记录当前运行环境**：从 `vending-api-candidate.service` 的 `WorkingDirectory` 获取仓库；核对 Web 服务同目录、Node/npm、同一受控 live 平面和私有目录。保存旧提交与两个服务的启动状态；不把 `.env`、令牌或生产数据写入 Git 或发布报告。
4. **停写与备份**：优雅停止 API、支付/其他写入维护进程和 Web 服务，确认 API 端口释放、金融单写者租约可取得。使用与受管 API 相同的私密环境执行 `verify:api-data`、`backup:api-data -- --label pre-release-admin-redesign --keep 30` 和 `verify:api-data -- --latest`。记录备份目录、清单 SHA256、命令退出码。在线文件复制不能作为回滚备份。
5. **Git 快进更新**：备份通过后保持停写，`umask 077`，从已批准的 Git 来源 `pull --ff-only`，核对 HEAD 等于批准 SHA。不要执行 `reset --hard` 或覆盖未知本地修改。源码来自 Git，不能在生产机临时编辑。
6. **安装与构建**：使用 Node 22.22.2 / npm 10.9.7，执行 `npm ci --include=dev`（构建需要 Vite、TypeScript 等工具），按发布门禁检查依赖目录属主和私有权限，运行类型检查、Linux 上的适用测试、工作区构建。最后单独执行 `npm run build:public-web`。只重建当前正式入口，不重装既有 systemd 单元或切换 Nginx。
7. **分层启动与验证**：先启动 API，健康与 production-readiness 均须 200，再恢复 Web。Spark 本机根页面 200、其 relay API 403；VNC 经 WireGuard 的页面与 API 均 200；最后复验公网根页面、登录、`/mobile/`、两个健康端点和未登录拒绝。任何一层不符立即停止后续发布。
8. **人工业务抽查**：实例管理员、服务商进出实例、商户/补货员权限入口；人员 → 管理 → 规则；待办详情；调拨核对；仓库处置核对；设置修改/取消/保存；浏览器前进后退与手机弹窗。生产写操作使用事先约定的验收对象，真实开门、退款、短信等必须另行明确授权。
9. **留存发布证据**：记录批准 SHA、旧 SHA、备份清单摘要、构建/测试结果、各层 HTTP 结果、浏览器异常与人工验收结果。通过公网验证后才标记发布完成；小程序包未上传时继续明确标记未上传。

正式 Web 构建参数保持后台 `VITE_API_BASE_URL=/api`，H5 由 `build:h5:deployment` 固定 `/mobile/` 和同源 `/api`，关闭验证码预览。微信构建保留 `https://vending.5gogogo.top/api`。不要使用本地预览启动器、演示账号、模拟数据或 `VITE_ALLOW_REMOTE_API_IN_LOCAL_DEV=true` 作为正式配置。
