## 设计原则

- 信息先分层：每屏优先展示状态、关键数字、主操作，说明文字收进提示卡或二级区域。
- 操作有路径：领取流程使用“资格校验、开柜、取货关门、完成结算”，补货流程使用“选择物品、填写批次、提交登记”。
- 组件统一：按钮、标签、表单、空状态、成功/警告提示、底部导航统一使用柔和绿色、暖橙、米白底、圆角卡片和轻阴影。
- 图标统一：页面内使用线性小图标；饮品、食品、日用品、扫码、柜机、补货、记录、成功、警告等图标均从同一组件体系输出。
- 角色清晰：受助端强调“今日资格、扫码开柜、附近柜机、领取记录”；商户端强调“补货入口、库存预警、批次登记、货物去向”。

## 页面方案

### 登录

- 首屏为插画卡片 + 手机号验证表单。
- 验证码按钮内嵌到验证码输入框右侧，减少纵向堆叠。
- 主按钮固定为“登录 / 身份识别”，注册与免责声明放在次级文本操作区。

### 审核中

- 顶部使用申请状态插画卡，卡片底部浮层展示“审核中/需修改”。
- 信息卡只保留手机号、账号类型、更新时间、驳回原因。
- 审核通过后回登录；驳回时主按钮变为“修改资料并重新提交”。

### 受助用户首页

- 今日资格卡优先显示可领取次数、已领取次数、可选种类与开放时段。
- 物资分类用饮品、食品、日用品图标卡展示。
- 主操作为暖橙“扫码开柜”，次操作为绿色描边“就近找柜机”。
- 最近柜机与最近记录作为下方辅助卡，避免首页信息堆叠。

### 附近柜机

- 地图/列表用分段控件切换。
- 柜机卡包含柜机缩略图、名称、位置、距离、在线状态、今日可领/低库存标签。
- 商户角色进入同页时，第二导航文案切为“补货”，卡片主操作为“补货 / 开门”。

### 扫码开柜流程

- 扫码或手动进入柜机详情后，显示流程进度条。
- 选择物品卡展示免费额度、库存、超额价格和批次到期。
- 开柜中页面使用状态面板 + 流程进度，突出“等待柜门响应/柜门已打开/取货后关门”。
- 失败结果页保留“原因 / 说明”卡，明确超时、柜机失败、距离异常、额度不足等原因。

### 领取结果与记录

- 结果页用成功/警告图标卡展示状态，下面才展示原因说明。
- 记录页采用时间线式列表，左侧图标表示领取成功或补扣，右侧保留数量标签。
- 商户记录页同时展示每日帮助概览、批次剩余和最近补货日志。

### 商户首页

- 顶部为暖橙概览卡，展示累计补货、商品模板、待处理预警。
- 常用操作为四宫格：开始补货、补货登记、补货记录、异常上报。
- 库存预警使用警告卡，突出需要处理的数量和原因。

### 补货表单

- 表单拆为三段：选择物品、填写批次、提交确认。
- 数量使用步进器，生产日期和预计到期清晰成对出现。
- 提交前确认卡展示模板、柜机、数量、批次号、预计到期。
- 成功后跳转结果页，并提示可在货物去向页追踪。

### 我的页面

- 顶部为账号身份卡，包含姓名、手机号、角色标签。
- 操作入口统一为大按钮：帮助中心、反馈问题、退出登录。
- 受助用户保留关怀模式切换。

## 组件落地

- `MenuIcon.vue`：统一线性图标，覆盖扫码、柜机、补货、记录、饮品、食品、日用品、成功、警告等场景。
- `theme.css`：统一色彩、圆角、阴影、按钮、标签、输入框、提示卡、指标条、操作卡。
- `FlowSteps.vue`：复用在开柜流程和补货填写流程。
- `CabinetHeroArt.vue`：保留公益柜机插画，用于登录、审核和引导区域。
- 底部导航：固定四项；受助端为“首页 / 附近柜机 / 记录 / 我的”，商户端为“首页 / 补货 / 记录 / 我的”，商户补货图标使用独立暖橙图标。
