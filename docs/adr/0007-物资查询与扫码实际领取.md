# ADR-0007 物资查询与扫码实际领取

## 状态

已接受，2026-09-19 用户明确要求将预约改为查询，并取消开门前的商品数量选择。

## 决策

- 新版移动端以物资查询替代预约入口。查询展示商品、库存及共享领取额度，不创建预约、不锁定库存。
- 扫码后用户点击“开门”，请求携带 `pickupMode: actual`，不传意向商品。服务端继续校验身份、业务时段、当天剩余额度与柜门就绪度；每天合计一件等既有规则仍有效。
- 开门事件固化领取方式。平台结算回调决定实际商品与完整数量；库存按实际扣减，额度按既有分配规则消耗，不按预选数量生成差异任务。实际多拿仍完整记录，额度耗尽后不能继续开柜。
- 同柜旧有效预约由可信开门或结算回调履约，其他本人预约在实际领取开始时释放。旧客户端在小程序审核过渡期继续使用原协议。
- 平台已确认的空取货自动按零件、零元完成，不扣库存和额度。后台每分钟补发未成功的已知零元结算，复用同一交易号；成功后停止重试。
- 自动补发必须持有单写租约、满足数据与审计门禁，不猜测缺少结算回调的事件，不再次开门。

## 与既有决策的关系

本决策替代 ADR-0006 中移动端选择商品、预约占用额度的新版交互安排；其分类树、共享额度池、历史精确分配和退款规则继续有效。旧选择式订单的历史核对语义保留。

## 验证

定向覆盖无预约开门、令牌重放、实际库存与额度扣减、空取货、旧预约兼容、非法模式与时段拒绝、零元补发退避和调度器写租约/审计门禁。实机开门不由自动化测试触发。
