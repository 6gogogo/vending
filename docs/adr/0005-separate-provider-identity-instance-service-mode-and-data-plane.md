# ADR-0005 分离服务商身份、实例服务类型与运行数据平面

## 状态

已接受

## 决策

服务商平台始终代表正式的平台级运营身份，不再用当前 Spark 进程的 `simulation` 或 `live` 数据平面给服务商账号贴标签。客户实例单独记录“模拟服务”或“正式服务”，实例的试运行、运行中、暂停仍由生命周期状态表达；部署进程继续用模拟与真实数据平面隔离数据和外部集成。

选择“正式服务”只确定实例的服务属性，不能绕过生产门禁。正式实例只有运行在与自身绑定的真实数据平面并通过生产就绪检查后，才可以对外宣称正式运行；历史实例缺少服务类型时，模拟快照保守补为模拟服务，真实快照补为正式服务，显式冲突则失败关闭。

## 影响

- 服务商登录和平台态顶部显示“正式服务商平台”，不再显示“模拟服务”。
- 服务商创建实例时必须明确选择服务类型；旧客户端未传字段时默认模拟服务，避免静默升级为正式服务。
- 进入实例后的会话携带该实例自己的服务类型，前端不再用全局公开配置猜测。
- 正式实例在模拟平面只保存待开通资料；服务商、首管理员和移动端都不能借该记录进入模拟业务。
- 真实数据平面的唯一客户实例必须是正式服务；模拟数据平面可以保留模拟实例及尚待生产开通的正式服务记录。
