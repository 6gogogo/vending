# ADR-0001 首版使用内存仓储和本地持久化文件

## 状态

已接受

## 背景

当前项目目标是先把公益智助柜的核心业务闭环跑通，包括注册审核、开柜、结算回调、库存批次、操作日志、仓库、预警和前后端页面流。正式数据层和更完整的数据分析能力会在后续阶段逐步替换和增强。

## 决策

首版后端使用内存仓储作为主要数据访问方式，并通过本地运行时文件保存状态。业务模块可以先围绕稳定的领域类型和接口形状迭代，不把开发节奏绑定在最终数据库设计上。

## 影响

- 可以快速调试业务流程、页面流和 SmartVM 回调模拟。
- 数据结构变化成本低，适合早期探索。
- 不适合作为长期生产数据层，后续需要迁移到 PostgreSQL / Redis 等正式存储。
- 架构建议不应仅因为存在内存仓储而要求立即替换数据库；只有当具体业务摩擦来自数据一致性、查询能力、并发或迁移需求时，才应重新讨论数据层。

## 后续

- 保持业务逻辑不要过度依赖数组可变实现细节。
- 深化库存批次、开柜结算、操作日志等模块的接口，为后续替换存储适配器留出空间。
- 当引入正式数据库时，新增 ADR 记录数据层选择、迁移策略和兼容范围。
