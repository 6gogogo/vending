# ADR-0006 使用树状货品分类与独立领取额度池

## 状态

已接受，等待产品界面审核后部署。

## 背景

原有领取规则直接给单个货品设置数量，无法表达“任意食品一件”或“任意物资三件”。简单把父级数量复制到所有子货品会重复放大额度，也会让商品提交顺序影响结果。

## 决策

- 货品目录使用一个唯一根节点“任意”，最多八层；每个货品只保存一个直接分类节点。
- 领取规则保存独立额度池，目标可以是分类节点或指定货品。父节点额度自动覆盖所有后代货品。
- 多个池按数量相加，但分配算法先使用最具体的可用池，再使用祖先池；同一组请求无论排列顺序如何都得到相同结果。
- 预约保存本次占用的额度池分配；结算流水保存实际消耗的精确分配；退款按原分配恢复，不根据后来移动过的分类改写历史。
- 分类移动、改名或停用必须先预览影响范围并携带 revision 提交。受影响的有效预约自动取消，避免用旧分类资格履约。
- 存量迁移采用“预览哈希 → 显式应用”。迁移保留货品、目录、库存和历史流水，清空旧模板、个人规则及旧总额度，并取消有效预约。预览后相关数据发生变化时拒绝应用。

## 影响

- 后台新增“货品分类”页面，并在人员详情增加分类额度配置；旧指定货品额度暂时保留用于兼容和分阶段迁移。
- 移动端继续读取兼容字段，并可读取新增的每货品可领数量和分类 revision；本阶段不调整移动端视觉页面。
- 旧库存流水没有额度池明细时，按实际货品兼容映射到当前有效池；新流水必须保存精确池分配。
- 分类树和额度规则仍属于当前实例的数据域。正式部署前必须先备份并只运行迁移预览，产品审核通过后才允许应用。

## 非目标

- 本决策不新增支付逻辑，不改变 SmartVM 柜机接口，也不在本阶段改动小程序页面布局。
- 本决策不自动推断业务分类；迁移只建立标准根节点并按现有货品分类生成可审查的直接归属。
