# 运行与测试说明

## 0. 统一配置和测试数据入口

现在按数据平面运行：

- 本地模拟入口可使用 `apps/api/.env` 与隔离测试数据；它保留测试账号、货品和审计证据。
- 真实入口必须使用 `VM_DATA_PLANE=live`、独立 `VM_DATA_ROOT` 与受控部署/密钥管理器，不能复用模拟 `.env` 或运行目录。
- 测试种子/空库命令只允许初始化全新的模拟数据平面，且必须在命令末尾显式追加 `--confirm-reset`；一旦已有业务数据、审计日志、上传、备份或金融租约证据，命令会拒绝覆盖。真实平面禁止通用测试种子和清空命令。
- 真实支付、短信、柜机凭据和真实库初始化见[真实入口配置与数据平面说明](真实入口配置与数据平面说明.md)。

说明：

- `SMARTVM_BASE_URL`、`SMARTVM_CLIENT_ID`、`SMARTVM_KEY`：模拟平面必须全部留空；网关会使用内存 mock。真实柜机平台参数只能由受控真实入口注入，不能写进本地模拟 `.env`。
- `AMAP_WEB_KEY`：后台地图选点用的高德 Web Key
- `AMAP_SECURITY_JS_CODE`：高德 JS API 新 Key 常用的安全密钥，地图脚本加载前会自动写入 `window._AMapSecurityConfig`
- `ALIYUN_PNVS_*`：阿里云号码认证短信服务的访问密钥、签名、模板与用途隔离方案
- `VERIFICATION_CODE_PROVIDER`：验证码服务模式，`mock` 表示本地测试码，`manual` 表示只接受后台签发的一次性人工码，`aliyun_pnvs` 表示真实号码认证短信验证码
- `VERIFICATION_CODE_PREVIEW_ENABLED`：是否在接口返回中附带测试验证码，真实短信模式建议改为 `false`
- `VM_DATA_PLANE` / `VM_DATA_PLANE_ID` / `VM_DATA_ROOT`：本地模拟入口应显式选择 `simulation`、使用至少 8 位的独立平面 ID，并由隔离根目录派生状态、审计、上传、备份和租约路径。
- `API_DATA_FILE`、`UPLOAD_DIR`、`SYSTEM_LOG_FILE`、`API_BACKUP_DIR`、`FINANCIAL_SINGLE_WRITER_LEASE_FILE`：仅用于旧式模拟路径；使用 `VM_DATA_ROOT` 时必须全部留空，不能混用。
- `ENABLE_LOCAL_MOCK_DEVICE_API`：默认关闭。只有使用隔离 `API_DATA_FILE` 的本地回环联调才可临时设为 `true`；生产或非回环监听仍会强制拒绝。
- `ENABLE_TEST_DEVICE_BOOTSTRAP`：默认关闭。仅隔离测试需要比赛测试柜机 `91120149` 时临时开启，避免测试设备污染日常数据。
- 验证码、Bearer 登录会话和注册资料草稿只保存在当前 API 进程内，不写入 `API_DATA_FILE` 或备份；API 重启后用户需要重新登录或重新获取验证码
- `API_HOST`：本地默认使用 `127.0.0.1`，避免 API 意外暴露到局域网；生产环境如需由反向代理接入再显式配置监听地址
- `TRUST_PROXY_HOPS`：默认留空并不信任转发头；只有 API 前方确有固定层数的可信反向代理时才填写层数，例如 `1`
- `DATABASE_URL`：PostgreSQL 迁移预留连接串；当前业务主数据仍由受控 JSON 账本保存，不会因填写此项自动切库
- `UPLOAD_DIR`：后台和 PC 端上传图片的实际落盘目录
- `SYSTEM_LOG_FILE`：系统级接口审计日志文件位置；敏感字段会递归脱敏，超长或过深内容会截断
- `PAYMENT_MODE`：支付运行模式。模拟平面只能为 `mock`；真实平面通常为 `real`，预约取货且 `VM_RESERVATION_ONLY_PICKUP=true` 时可设为 `disabled`。真实模式不会回落到模拟支付。
- `PAYMENT_PROVIDER_TIMEOUT_MS`：真实支付平台外呼超时，默认 `15000` 毫秒；超时后返回可恢复错误，不让用户无限等待。
- `PAYMENT_MOCK_ENABLED`：旧版兼容开关，`PAYMENT_MODE` 优先。旧配置中 `true` 等价 `PAYMENT_MODE=mock`，`false` 等价 `PAYMENT_MODE=real`，留空等价自动模式。
- `SMARTVM_TIMEOUT_MS`：柜机查询、开门、付款回写和退款请求超时，默认 `15000` 毫秒。
- `SMARTVM_ALLOWED_NOTIFY_ORIGINS`：额外允许的柜机付款回写 URL 来源。默认只允许 `SMARTVM_BASE_URL` 的同源地址；确有分离回写域名时才显式填写，多个用英文逗号分隔。
- `WECHAT_PAY_*` / `WECHAT_MINI_*` / `ALIPAY_*`：直连微信支付和支付宝小程序支付的商户、网关、回调和付款人身份换取参数；要确认真实支付状态，优先看后端启动日志里的 `[支付自检]`，或登录后台进入“系统设置”查看“支付自检”面板。
- `OPENAI_API_KEY`：模拟平面必须留空，避免测试业务上下文或测试密钥被外发；真实平面中 AI 仍为可选功能，启用前应完成供应商、数据处理与审计审批。

### 支付模式与自检

按数据平面启动时，支付模式没有自动回退：

- `VM_DATA_PLANE=simulation` 必须配合 `PAYMENT_MODE=mock`。即使误填真实商户凭据也不会获得真实支付通道。
- `VM_DATA_PLANE=live` 必须在 `NODE_ENV` 或 `APP_ENV` 为 `production` 的受控运行态启动。即时领取配合 `PAYMENT_MODE=real`；预约取货可配合 `PAYMENT_MODE=disabled`，但支付/退款账本必须为空。
- `PAYMENT_MODE=auto` 仅是旧配置兼容语义；按数据平面启动的 API 会拒绝它，不能用于本地、测试或真实入口。

后端启动成功后会输出类似：

```text
[支付自检] 请求模式=模拟（来源 PAYMENT_MODE）；总体=模拟支付；模拟完成接口=可用
```

后台也可在“系统设置”页查看同一份支付自检结果。接口为 `GET /api/payments/diagnostics`，需要后台系统设置查看权限。

### PostgreSQL / Prisma 迁移

当前已经预留 PostgreSQL + Prisma 结构，迁移顺序建议为：

```bash
npm ci
npm install --workspace @vm/api @prisma/client
npm install --workspace @vm/api --save-dev prisma
npm run db:api:generate
npm run db:api:push
npm run db:api:migrate-json
```

`db:api:migrate-json` 会读取 `API_DATA_FILE` 指向的 `store.json`，并把用户、柜机、货品、订单、支付单、回调、审计日志等写入 PostgreSQL。

当前项目按 Prisma 7 配置：数据库连接串放在 `apps/api/prisma.config.ts` 读取的 `DATABASE_URL` 中，`apps/api/prisma/schema.prisma` 里只保留 `provider = "postgresql"`。

### 预约与多退少补联调点

结算金额以柜机 `callbacks/settlement` 回调里的 `detail` 商品明细为准。后端会按实际商品重新计算免费额度、应付金额和差额：

- 实际应付高于预估时，事件会标记为 `supplement_pending`，并阻止该用户继续开柜或预约，直到支付成功回写平台，或管理员调用 `POST /api/cabinet-events/event/:eventId/billing-confirmation` 确认。
- 实际应付低于预估时，事件会记录 `billingDeltaType=refund`，后续退款链路可按该差额处理。
- 移动端默认仍走关门后支付，支付金额读取事件的实际应付金额。

预约接口：

- `GET /api/reservations/settings`：读取预约规则。
- `PATCH /api/reservations/settings`：管理员设置是否启用、预约保留分钟数、超时封禁次数，默认保留 60 分钟、超时 3 次封禁。
- `POST /api/reservations`：普通用户预约当前柜机所选货品。
- `GET /api/reservations/my`：普通用户查看自己的预约。
- `POST /api/reservations/:id/cancel`：取消预约。
- `POST /api/reservations/users/:userId/reset-timeouts`：管理员重置用户预约超时次数。

### 补货、补扣与撤销联动

补货和补扣接口现在都要求前端先二次确认，并在请求体带上 `confirmed: true`。补扣可以传入明确的 `batchConsumptions`；如果没有指定批次，后端会按“保质期最短、再按创建时间最早”的顺序扣减，并把实际扣到的批次写入库存流水和批次消耗追踪。

`POST /api/merchant-restocks` 还必须携带 `cabinetEventId`。该事件必须属于当前用户和目标柜机、明确为有商品入柜的补货事件，并已进入 `closed` 或 `settled`；同一事件重复提交相同明细只返回原批次，提交不同明细会被拒绝。

旧接口 `POST /api/inventory-orders/refund` 只用于整单全额退款，并在调用柜机退款前校验订单、柜机、金额和退款标识；部分退款统一走支付单退款接口，累计全额后才释放领取额度。

操作日志撤销会同步写入反向库存流水、恢复或扣减对应批次，并把原补扣的批次消耗追踪标记为已撤销，避免日志状态、柜机库存和批次去向不一致。

用户通过 APP 提交反馈后，管理员手动确认/处理该反馈时，后端会在告警记录上写入用户通知内容；用户下次进入 APP 首页时会弹出“反馈已接受”的提示。

### AI 助手配置

如果要启用后台里的 `AI 工作台`，默认只需要在：

```text
apps/api/.env
```

里补一项：

```env
OPENAI_API_KEY=你的 OpenAI Key
```

当前后端已经按 OpenAI `chat/completions` 格式封装好了五类能力：

- 单次开柜异常诊断
- AI 运维晨报 / 日报
- AI 补货与布局建议
- AI 反馈分流与回复草稿
- AI 策略优化建议

默认值如下，一般不用改：

```env
OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
OPENAI_BASE_URL_EXACT_HOST_ALLOWLIST=
OPENAI_MODEL=qwen2.5-vl-72b-instruct
OPENAI_TIMEOUT_MS=30000
```

默认只接受 HTTPS 公网主机，并拒绝 `localhost`、回环、链路本地、私网、未指定和保留 IP（含 IPv4/IPv6）。如果确需连接本机或私网模型，必须把 URL 中的主机逐个写入 `OPENAI_BASE_URL_EXACT_HOST_ALLOWLIST`，多个值用英文逗号分隔；只匹配规范化后的完整主机名或 IP，不支持通配符、URL、端口或子域继承。精确允许后可使用 HTTP，但账号密码、查询参数和 URL 片段仍会被拒绝。

该应用层校验不会把 DNS 名称“可靠证明”为公网地址，也不能单独阻止 DNS 重绑定。生产环境仍应通过固定可信 DNS、出网代理或防火墙限制 AI 服务实际可达的目标；允许名单中的 DNS 主机也应视为显式信任。改用兼容 OpenAI 协议的公网中转网关时，只需调整 `OPENAI_BASE_URL` 和 `OPENAI_MODEL`；私网模型还需同步配置上述精确主机允许名单。

### 路径解析规则

现在后端的这两个路径：

- `API_DATA_FILE`
- `UPLOAD_DIR`

默认都按 `apps/api` 目录为基准解析，不再依赖你从哪个目录启动进程。

例如：

```env
API_DATA_FILE=runtime-data/store.json
UPLOAD_DIR=runtime-uploads
```

实际会分别落到：

```text
apps/api/runtime-data/store.json
apps/api/runtime-uploads
```

### 本地审查门禁

不连接真实短信、支付、柜机或公网服务时，先使用本地 mock 配置，再从仓库根目录执行：

```powershell
npm run check:local
```

该命令依次运行全工作区类型检查、API 单元/安全回归、库存与数据完整性 smoke，以及前端关键流程静态安全检查。准备发布候选版本时再运行包含所有前端目标构建的完整门禁：

```powershell
npm run check:local:full
```

这两个命令都不会替代真机、真实支付或公网部署后的验证；本地审查期间应保持 `API_HOST=127.0.0.1`、`PAYMENT_MODE=mock`、`VERIFICATION_CODE_PROVIDER=mock`，并留空真实外部凭据。

如果你未来用 PM2、NSSM、systemd 或计划任务启动，并且不想依赖项目目录写入，也可以直接改成绝对路径，例如：

```env
API_DATA_FILE=/data/vending-machine/store.json
UPLOAD_DIR=/data/vending-machine/uploads
```

### 初始化测试数据

如果要创建一个全新的默认测试数据平面，必须使用明确确认参数：

```powershell
npm run init:api-data -- --confirm-reset
```

不带 `--confirm-reset` 时命令会以退出码 2 拒绝执行。该命令不再原地覆盖已有文件：只要当前目标已有 `store.json`、非空审计日志、上传文件、备份或租约，它就会失败关闭以保留审计证据。需要新的测试状态时，必须显式创建完整隔离平面，例如：

```powershell
$env:VM_DATA_PLANE = 'simulation'
$env:VM_DATA_PLANE_ID = 'simulation-reset-01'
$env:VM_DATA_ROOT = "$PWD\.local-runtime\simulation-reset-01"
$env:API_DATA_FILE = ''
$env:UPLOAD_DIR = ''
$env:SYSTEM_LOG_FILE = ''
$env:API_BACKUP_DIR = ''
$env:FINANCIAL_SINGLE_WRITER_LEASE_FILE = ''
npm run init:api-data -- --confirm-reset
```

生产环境不应把模拟初始化命令当作日常发布步骤；真实入口只能走受控真实库初始化，不能使用本节模拟种子命令。需要回到已知状态时，应走受控备份恢复。

### 初始化为空库

如果要创建一个全新的模拟空库，而不是初始化调试种子数据，使用：

```powershell
npm run init:all-data -- --confirm-reset
```

这条命令只对没有任何历史证据的目标生效，并会：

- 将 `API_DATA_FILE` 指向的业务数据写成空库
- 清空 `SYSTEM_LOG_FILE` 系统审计日志
- 清空并重建 `UPLOAD_DIR` 上传目录
- 禁止后端启动时自动补回测试柜机 `91120149`

`--keep-uploads` 仅适用于目标上传目录本来为空或不存在的首次初始化；它不会绕过已有上传证据的拒绝保护：

```powershell
npm run init:all-data:keep-uploads -- --confirm-reset
```

执行后再启动后端，让内存中的数据从新空库文件加载。

脚本还会在写入前拒绝数据文件、系统日志和上传目录互相重叠，以及拒绝清空文件系统根目录、API 工作区或其父目录。真实平面始终拒绝该命令。

## 0.1 迁移到新机器前的环境要求

如果后端和 PC 端要迁移到另一台机器，最低要求建议按下面准备：

- Node.js：建议 `22 LTS` 或 `24`
- npm：建议 `10+`
- 可写目录权限：
  - `API_DATA_FILE` 指向的目录必须可写
  - `UPLOAD_DIR` 指向的目录必须可写
- 网络连通：
  - PC 前端浏览器必须能访问后端 `http://<你的地址>:<端口>/api`
  - 如果要用地图，高德 key 必须有效
  - 如果要接真实柜机平台，`SMARTVM_*` 必须配置完整
- 浏览器环境：
  - PC 端后台需要现代浏览器，建议 Chrome / Edge 最新稳定版

## 0.2 远端部署同步流程

当前约定按“本地验证 -> Git 提交 -> 公网服务器拉取 -> 公网构建运行 -> 公网验证”的方式发布，避免直接在服务器上改代码。

完整门禁要求见：

```text
docs/发布与公网部署验证流程.md
```

下面只保留常用命令摘要。

本地流程：

```bash
npm run typecheck --workspaces --if-present
npm run build --workspaces --if-present
npm run build:weixin --workspace @vm/mobile
git status --short
git add <本次需要发布的文件>
git commit -m "本次发布说明"
git push <本地远端名> codex/UI
```

当前本地常用远端名是 `vending`，可用 `git remote -v` 确认。

```bash

git pull --ff-only origin codex/UI
npm ci
```

当前服务器上的远端名是 `origin`，可用 `git remote -v` 确认。

如果服务器直连 GitHub 出现 `GnuTLS recv error` 或 TLS 中断，可临时走服务器本机代理重试：


### Spark 公网部署

Spark 公网发布以[发布与公网部署验证流程](发布与公网部署验证流程.md)为唯一门禁。先在同一进程管理器中优雅停止 API、支付维护和静态服务，确认端口与金融单写者租约已释放后，备份并校验运行数据；不得使用 `fuser -k` 或其他强制杀进程方式。

构建应使用 `npm run build --workspaces --if-present` 和 `npm run build:public-web`。API 与静态服务都必须由既有的受管服务（例如 systemd user service）启动，不能临时改用 `nohup` 或 `npx serve`，以免产生双实例或漏掉 `/mobile/` 静态产物。

`npm run start:public-web` 默认只在 `127.0.0.1:5795` 提供后台和移动 H5。当前最终 Spark 部署使用受管 `vending-public-web.service` 绑定 `10.66.66.2:5795`；它在 Spark 内部以受限 relay 把同源 `/api/*` 送到仍固定为 `API_HOST=127.0.0.1`、`TRUST_PROXY_HOPS=1` 的 API。API 不直接绑定 WireGuard 或公网地址，relay 必须删除客户端带入的转发头并重建受信任头。VNC 只保留 Nginx：HTTPS 的 `location /` 与 `location ^~ /api/` 均代理到 `http://10.66.66.2:5795`，不使用 VNC Unix socket edge、私网 API relay 或 VNC 本地 Node 服务。完整受控切换、回滚与验收步骤见 [Spark 公网最终入口链路](Spark公网最终入口链路.md)。

VNC 不需要开放 Spark 新公网端口，也不得将 Spark `:5795` 或 API 原始端口直接暴露到公网。入口切换之前，Spark 本机只核对根路径为 `200`、回环 API 健康为 `200`，而本机直连 `:5795/api/health` 必须为 `403`，证明 relay 没有放宽来源限制；再从 VNC `10.66.66.1` 核对根路径和 `:5795/api/health` 都为 `200`。切换后从公网 HTTPS 验证后台、同源 API 和移动入口。旧 VNC vending 服务只在独立的公网回归和稳定观察之后按具体受管 service 优雅退役，不能按端口批量 kill。

注意：

- 不要把服务器密码、第三方密钥、真实 `.env` 内容提交到 Git。
- `apps/api/runtime-data/` 是运行数据目录，已经忽略，不随代码发布。

## 4. 移动端现在到底是什么运行方式

当前 `npm run dev:mobile` 对应的是：

```bash
uni -p h5
```

这表示它运行的是 **H5 版本**，本质上是浏览器网页，不是“模拟一个带手机边框的真机界面”。

所以你现在看到“只有一个背景”的情况，通常意味着：

- 你打开的是 H5 页面
- 页面逻辑可能没加载成功，或者
- 你没有进入正确页面流程

它不是手机模拟器，只是把 uni-app 输出成网页来预览。

### 移动端接口地址该怎么配

移动端默认会读取：

```text
VITE_API_BASE_URL
```

示例文件已经放在：

```text
apps/mobile/.env.example
```

如果你只是用电脑里的微信开发者工具模拟器，并且已经勾选了“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”，可以写：

```env
VITE_API_BASE_URL=http://127.0.0.1:4000/api
```

如果你还在开发者工具里做局域网联调，也可以改成你电脑的局域网 IP，例如：

```env
VITE_API_BASE_URL=http://192.168.1.20:4000/api
```

但这条不适用于微信小程序真机、体验版和正式版。`fail url not in domain list` 的根因通常是下面几种之一：

- 请求地址还是 `http://...`
- 请求地址是公网 `IP:端口`
- 没有把对应域名配置到微信公众平台“服务器域名”
- 开发者工具没有勾选“不校验合法域名...”

原因是：

- 开发者工具模拟器运行在你电脑上
- 真机运行在手机上
- 手机里的 `localhost` 指向手机自己，不指向你的电脑

微信小程序正式可用的口径应当是：

```env
VITE_API_BASE_URL=https://your-domain.com/api
```

并且在微信公众平台配置：

- 开发管理
- 开发设置
- 服务器域名
- request 合法域名：`https://your-domain.com`

### 当前 App / 小程序入口联调流程

新的移动端入口已经改成：

- 初始页：只显示 `登录 / 注册 / 反馈`
- 登录页：只输入 `手机号 + 验证码`
- 注册页：先选身份，再填写资料
- 审核状态页：只显示 `待审核 / 已驳回`

本地联调顺序建议固定为：

1. 启动后端：`npm run dev:api:once`


4. 重新执行小程序或 H5 构建
5. 进入移动端初始页测试：
   - `注册`
   - `审核`
   - `登录`
   - `退出登录`

### 后续切换线上服务器 IP 的方法

后续如果后端换成开放的线上服务器，只改环境变量，不改业务代码。

### 登录 / 注册 / 审核状态怎么验证

- 未登记手机号：
  先在登录页请求验证码，再点登录，应提示“未登记，请先注册或反馈”

### 后台地图选点

后台地图选点使用高德 Web JS API。先在：

```text

```

```env
AMAP_WEB_KEY=你的高德WebKey
```

### APP 距离排序

1. 小程序或 App 获取当前定位
2. 把当前经纬度传给本地后端

### 小程序和 App 需要的定位权限

如果你要让移动端稳定显示“我的位置”、按距离排序并查找最近柜机，至少需要这两层权限：

- 小程序 / App 业务权限：允许调用定位能力
- 手机系统权限：允许当前应用访问位置信息

当前项目已经在页面逻辑里调用 `uni.getLocation`。你后续上线或真机测试时，还需要确认：

- 微信小程序已申请并说明 `scope.userLocation` 用途
- Android / iOS 真机已对该应用开启定位权限
- 若后续要做持续定位或后台定位，再单独补申请；当前仅使用前台单次定位

如果你后面要走微信小程序正式发布，建议把定位权限说明写成类似：

```text
用于显示附近柜机、计算距离并帮助用户找到最近可用柜机
```

### 切到线上服务器时需要改什么

1. 把 `apps/mobile/.env.local` 或对应环境文件中的 `VITE_API_BASE_URL` 改成线上 API 地址
2. 把 `apps/admin-web/.env.local` 中的 `VITE_API_BASE_URL` 改成线上 API 地址
3. 如果后台部署域名变了，确认高德控制台里对应域名已加入允许范围
4. 重新构建后台和小程序

## 12. 图片上传保存在哪里

当前图片上传分两部分：

1. 文件本体保存到后端运行目录：

```text
runtime-uploads
```

2. 图片访问地址保存到后端数据记录中的 `imageUrl` 字段

当前业务运行态会原子写入 `API_DATA_FILE`，上传文件本体保存在 `UPLOAD_DIR`，图片 URL 会随业务数据一并持久化。迁移 PostgreSQL 前仍要同时备份数据文件和上传目录。

上传端会验证真实文件结构、图片尺寸和像素总量，仅接受 PNG、JPG、静态 GIF、WebP；动画图片、仅伪造文件头的内容和超大解码尺寸会被拒绝。静态文件响应会附带 `nosniff` 等安全头。若未配置 `PUBLIC_BASE_URL`，上传接口只返回站内相对地址，避免信任客户端传入的 `Host`。

## 柜机回调日志落库

- 门状态、结算、补扣、付款成功、退款回调都会进入后端日志链路。
- 原始回调报文会落到后端持久化文件中的 `callbackLog`。
- 当前默认持久化文件路径：`apps/api/runtime-data/store.json`
- 管理端查看设备回调日志接口：`GET /api/cabinet-events/callback-logs`
